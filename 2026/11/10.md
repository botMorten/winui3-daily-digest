## Community experience

- **PullYard: a real WinUI 3 app, with an intentionally hybrid rendering strategy.** Developer vaache’s November 10 retrospective describes maintaining separate SwiftUI, WinUI 3 and GTK 4 implementations of a pull-request review client. Windows uses native navigation and lists, but WebView2 for diffs and agent chat; lazy file bodies and CSS `content-visibility` avoid laying out off-screen diffs. The author reports a roughly 63 MB self-contained x64 installer and ongoing chat-scrolling fixes—not an independently measured performance victory. Useful lesson: optimize the expensive screen, rather than treating “native” as an all-or-nothing badge. The Windows README confirms .NET 8/Windows App SDK 1.8 and x64/ARM64 installer/portable builds.
  <https://dev.to/vaache/one-app-three-native-uis-what-i-learned-building-the-same-app-in-swiftui-winui-3-and-gtk-4-la7>

- **Missing WinUI item templates: Microsoft explains the filter and expected delivery vehicle.** Update to the November 7 report, with new maintainer clarification November 9: Lauren Ciha explains that older Visual Studio templates require both `CSharp` and `WindowsAppSDK` capabilities, whereas referencing the standalone WinUI package supplies `WinUI`. The corrected filter accepts either SDK capability and is **expected in Visual Studio 18.12**, not delivered simply by changing the SDK NuGet version. The previously reported explicit project-capability workaround remains relevant meanwhile; this is a maintainer explanation and expected timeline, not proof the fix has shipped.
  <https://github.com/microsoft/WindowsAppSDK/issues/6960#issuecomment-6750980870>

## News/releases

- **WinApp CLI 0.8 gets its developer-facing announcement: live inspection plus actionable profiling.** Microsoft’s November 9 post introduces experimental DevTools for C# and C++: inspect visual trees, source locations, bindings and layout, try property changes, and attach persistent comments for a coding agent. Live property edits **do not modify source** and disappear on restart. ETW profiling can identify expensive XAML parsing/layout work, but its UI-thread timings are not GPU execution or displayed FPS. Also useful: C++ project build/MSIX packaging, a WebView2 inspection-hang fix and duplicate-reference-build fixes. The package itself was published November 6 Pacific; this is fresh announcement coverage, not a package released today. No newer Windows App SDK package was found in the direct release-list check.
  <https://devblogs.microsoft.com/ifdef-windows/windows-app-development-cli-v0-8/>

## microsoft-ui-xaml — past 24 hours

**Exact window:** November 9, 2026, 08:30 PST–November 10, 2026, 08:30 PST. Direct, paginated API inspection covered 18 updated issues of all states, excluding 32 PR records from issue counts. GitHub Discussions is enabled; all 649 discussion threads and their comment/reply trees were checked, with **no verified in-window Discussion activity**.

- **NavigationView explicit selection/reentrancy repair merged.** Issue #6511 dates to December 2021; on November 10 UTC, PR #12252 merged and the issue closed. The change permits explicit selection when `SelectsOnInvoked=false`, without a spurious invocation event, and guards reentrant selection/source changes. Practical impact: programmatic selection should behave more predictably. **Merged source, not a verified shipped package.**
  <https://github.com/microsoft/microsoft-ui-xaml/issues/6511>

- **Back-button styles fixed at app-resource scope—with a compatibility wrinkle.** PR #12559 merged November 10 UTC, closing #9536 and two related older issues. It makes the intended back-button styles available through `XamlControlsResources`. Keyed app buttons now use animated back icons and can ignore custom `Content`/`FontSize`; apps needing their old custom glyph should use their own style key. Built-in NavigationView is unchanged. **Source fix only; package delivery unverified.**
  <https://github.com/microsoft/microsoft-ui-xaml/pull/12559>

- **New custom-enum `x:Bind` fallback failure.** Filed November 9, #12618 provides a repro where `XamlBindingHelper.ConvertValue` fails for a public custom enum on SDK 2.6.5, breaking `FallbackValue`, while built-in enums work. Moving fallback handling into the view model is described as an alternative. **Reporter evidence only:** the sole reply was automated triage, not human maintainer confirmation.
  <https://github.com/microsoft/microsoft-ui-xaml/issues/12618>

- **Fullscreen one-pixel gap gets concrete new evidence, not a finished fix.** The October 1 issue #12138 received November 10 UTC before/after captures and an open repair PR. JesseCol reports correcting a 1024×767 bridge at y=1 to 1024×768 at y=0 by checking native frame styles before reserving a border pixel. This narrows the diagnosis, but the PR is **unmerged** and author results were not independently reproduced.
  <https://github.com/microsoft/microsoft-ui-xaml/issues/12138#issuecomment-6758357071>

- **TableView’s selection indicator may change direction rather than mimic ListView.** On the October 12 feedback issue, harshit7962 replied November 10 UTC that a row-selection UX review led to plans to remove the left selection pill. That is a contributor’s stated upcoming design change—not implemented behavior, a release commitment, or broad community consensus.
  <https://github.com/microsoft/microsoft-ui-xaml/issues/12240#issuecomment-6759224923>
