## Community experience

- **Machitan puts WinUI 3 to work as an alternative desktop shell.** Reddit r/coolgithubprojects, posted **November 20 Pacific**. The author’s early public test combines a taskbar, Start menu, live DWM previews, tray forwarding and privacy indicators using .NET 10, Windows App SDK 2.7.0 and native Win32 interop—no WebView. In visible comments, the author clarified that it **hides Explorer’s shell rather than replacing explorer.exe**, with a guardian intended to restore the taskbar after a crash; another user requested separate launcher/running-app bars. An interesting interop-heavy adoption example, not a production-readiness verdict; installers are unsigned. <https://www.reddit.com/r/coolgithubprojects/comments/1y1qs6n/machitan_an_alternate_windows_11_shell_made_with/> · <https://github.com/mujairkitten/machitan>

## News/releases

- **DevOpsToolsInstaller 3.1.4: a shipping WinUI workstation tool polishes navigation and diagnostics.** GitHub release, **November 21 Pacific**. The native WinUI 3 app adds context-sensitive `Ctrl+K` actions, dynamically discovered catalog categories and theme-aware notification badges, alongside runtime-shadowing detection and more resilient version parsing. The author also reports WinGet community distribution and automated publishing: a substantial tooling dashboard with GUI and headless workflows, rather than another attractive mockup. Release claims were not independently tested. <https://github.com/NotHarshhaa/DevOpsToolsInstaller/releases/tag/v3.1.4>

- **Catch-up — RHI 2.9.5 expands controller-friendly collection management.** GitHub release, **November 20, 06:10 PST**, missed before yesterday’s cutoff. Beyond game-mod features, this WinUI app now has a searchable collections-management window usable with a controller, Ctrl/Shift multi-selection, live color-theme previews and a streamlined in-app update window that preserves the install location. These are app-level UX/shipping improvements; this release does **not** establish a new framework-level freeze fix. <https://github.com/RankFTW/RHI/releases/tag/RHI-2.9.5>

- **Catch-up — Rust for Windows demonstrates native WinUI controls plus Direct2D.** Microsoft’s windows-rs update, **November 19**. A new Task Manager sample combines `windows-reactor`’s WinUI 3-backed controls with `windows-canvas` charts; synthetic-data mode supports exploring sorting, process trees and history without touching real processes. The team describes event-delivery, keyed-lifetime, scrolling and accessibility improvements, but says the work is on `master` for upcoming releases and **not all published on crates.io**—sample/source guidance, not a newly shipped umbrella-crate upgrade. <https://github.com/microsoft/windows-rs/issues/5445>

## microsoft-ui-xaml — past 24 hours

**Exact window:** November 20, 08:30 PST ≤ activity < November 21, 08:30 PST. Issues and GitHub Discussions inspected directly, including activity on older threads.

- **Issue — ListView reorder leaves stale selection indicators.** Originally February 2023; **November 20:** PR 12622 merged and the issue closed. Drag/reorder animation locks could leave unselected or recycled items looking selected; the change cleans up indicators when their fade cannot complete. **Merged source, not a shipped package.** <https://github.com/microsoft/microsoft-ui-xaml/issues/8271> · <https://github.com/microsoft/microsoft-ui-xaml/pull/12622>

- **Issue — Grouped TableView scrolling triggers a layout cycle.** **New November 20:** a 2.6.5-experimental repro collapses ten 300-item groups, expands one, then scrolls into an exception. A project is attached; no human confirmation, workaround or linked fix. Test grouped expand/collapse behavior before adopting this experimental control. <https://github.com/microsoft/microsoft-ui-xaml/issues/12786>

- **Issue — ARM64 XAML compiler: optimization versus replacement.** Originally July; **November 20 Pacific:** contributor dotMorten distinguishes October’s merged metadata-lookup optimization from proposed native compiler work. Newly linked PR 12394 remains **open/unmerged**; real ARM64-host validation is still outstanding. This explains the roadmap, not a newly available native compiler. <https://github.com/microsoft/microsoft-ui-xaml/issues/11237#issuecomment-7053819999> · <https://github.com/microsoft/microsoft-ui-xaml/pull/12394>

- **Issue — Top NavigationView behaves differently for programmatic selection.** **New November 21:** on 2.7.0, setting `SelectedItem` to an overflow item reportedly fails to promote it into the visible row; the first selection also lacks its indicator, unlike mouse selection. C#/XAML supplied; no human response or verified fix. <https://github.com/microsoft/microsoft-ui-xaml/issues/12795>

- **Discussion — CppWinC’s compatibility gate remains.** Originally September 25; **November 20 body edit**, verified against yesterday’s text: the author claims broader WinUI coverage but still excludes complete WinUI 3 support until Gallery code-behind handling works. Treat this as community compiler progress, not proven application compatibility. <https://github.com/microsoft/microsoft-ui-xaml/discussions/12048>

- **Discussion — F# and Elmish directly over WinUI.** **New November 21:** WinUI.Elmish introduces typed builders and virtual-node diffing. Its docs require experimental code-first DataTemplate/theme APIs and warn that child reordering can recreate elements. No GitHub releases listed: promising source to explore, not a stable, independently tested framework. <https://github.com/microsoft/microsoft-ui-xaml/discussions/12794>
