## Community experience

- **Catch-up + fresh fixes — Nebula pairs WinUI chrome with a custom photo renderer.** Public source project created Nov 13; fixes Nov 17. Its author demonstrates 50,000 photos using a C++ Direct3D 11 `SwapChainPanel`, **not 50,000 XAML image controls**; WinUI supplies panels/navigation and local AI supplies semantic search. Real users reported x64 launch/import failures; source commits now address architecture selection and enforce the renderer’s 100,000-photo cap. No packaged release or independent benchmark verified. <https://github.com/lcoutodemos/Nebula> · <https://github.com/lcoutodemos/Nebula/issues/1>

- **Update — missing VCLibs deployment dependency: workaround confirmed.** WindowsAppSDK #6976, opened Nov 15 PST; replies Nov 16. After yesterday’s ARM64/F5 failure, a community member suggested `WinUISDKReferences=false`; the reporter confirmed it worked. This addresses the injected C++ dependency in that repro—not a blanket recommendation for all WinUI projects or a shipped framework fix. <https://github.com/microsoft/WindowsAppSDK/issues/6976#issuecomment-6930641854>

- **Fullscreen switching exposes an AppWindow lifetime problem under page heap.** WindowsAppSDK #6981, Nov 17. A developer supplies a plain-Win32/no-XAML repro on SDK 2.6.5: `SetPresenter(FullScreen)` with an extended title bar reportedly releases an already-freed accessibility provider. Their default-title-bar control did not crash; normal runs without page heap also looked fine. Relevant to WinUI’s shared windowing layer, but still reporter-only—not a confirmed security finding or fix. <https://github.com/microsoft/WindowsAppSDK/issues/6981>

## News/releases

- **Updated VS Code quickstart spells out packaging traps.** Microsoft Learn, dated Nov 16; metadata updated 09:41 PST. The agent-assisted WinUI guide documents a CLI-to-Store path, including a successful `dotnet run` before F5 and development-versus-distribution signing. First Store submission still requires Partner Center; CLI updates require an Entra-linked account and currently support free products only. Documentation guidance, not an independently tested workflow. <https://learn.microsoft.com/en-us/windows/apps/develop/ai-assisted/quickstart>

- **Catch-up — ReactiveUI 27 changes WinUI upgrade planning.** ReactiveUI release, Nov 15 UTC, not previously covered; `ReactiveUI.WinUI` 27.0.0 is on NuGet. Modern targets move to .NET 10/11 and drop .NET 8/9: this is not a routine package bump for older apps. Disabled/unset implicit-usings settings also mean checking explicit ReactiveUI/binding namespaces; upgrade related packages together. <https://github.com/reactiveui/ReactiveUI/releases/tag/27.0.0>

## microsoft-ui-xaml — past 24 hours

**Exact window:** November 16, 08:30 PST → November 17, 08:30 PST. Direct API inspection covered 27 updated issues of all states, excluding 70 PRs, and all 649 Discussion trees, including older comments/replies. **No in-window Discussion activity found.** Highlights below are **Issues**, not Discussions.

- **#12712 — .NET 11 Store-MSIX duplicate PDBs: reporter confirms recovery.** Opened Nov 16; Nov 17 follow-up says updating `Microsoft.Windows.SDK.BuildTools.MSIX` in **every project, including dependencies**, deleting `bin/obj`, and restarting VS restored Store packaging. Updating only the app had failed. Separately, the related #6353 AOT/subfolder case gained a contributor reply saying a fix is prepared—not released; don’t assume the same workaround solves both. <https://github.com/microsoft/microsoft-ui-xaml/issues/12712#issuecomment-6948449951> · <https://github.com/microsoft/WindowsAppSDK/issues/6353#issuecomment-6931419709>

- **#12138 — fullscreen one-pixel gap moves from proposal to merged source.** Originally Oct 1; on Nov 16 PR #12619 merged and JesseCol stated, “not currently in a release.” The practical change is source-level resolution, not an SDK users can install today. This is separate from the new provider-lifetime report above. <https://github.com/microsoft/microsoft-ui-xaml/issues/12138#issuecomment-6924464268>

- **#11183 — new diagnosis for silent CLI XAML compilation failure.** Originally June 19 Pacific; new Nov 16 PST comment attributes `XamlCompiler.exe` exit-code 1 to an embedded-resource-name mismatch throwing `MissingManifestResourceException`, unlike the in-process MSBuild compiler. A useful, specific community diagnosis for “works in VS, fails clean CI”; not a maintainer-confirmed fix. <https://github.com/microsoft/microsoft-ui-xaml/issues/11183#issuecomment-6935426535>

- **#12726 — NativeAOT template-root cast failure.** New Nov 17 report on 2.6.5 says an app-defined `DataTemplate` root triggers `E_NOINTERFACE` in generated `x:Bind` code; wrapping it in framework `Grid` is the proposed workaround. No independent reproduction or maintainer confirmation yet. <https://github.com/microsoft/microsoft-ui-xaml/issues/12726>

- **#12730 — experimental TableView selection blocks a migration.** New Nov 17 consolidated report says read-only selection properties and missing item-to-index/selection APIs prevent restoring selection, deep links, and MVVM-driven selection. This is one developer’s concrete migration blocker, not evidence that the whole control is unusable; no substantive maintainer response was verified. <https://github.com/microsoft/microsoft-ui-xaml/issues/12730>
