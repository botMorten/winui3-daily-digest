## Community experience

- **Missing symbols reported immediately on 2.6.5.** WindowsAppSDK issue, November 3: <https://github.com/microsoft/WindowsAppSDK/issues/6932>. A developer reports that the x64 `Microsoft.UI.Xaml.dll` 3.3.0.0 lacks its corresponding PDB on Microsoft's public symbol server. There was no maintainer confirmation or response at inspection. If native crash diagnosis is part of your upgrade validation, check symbol availability rather than assuming it; this is a reporter's finding, not an independently tested server outage.

- **Desktop automation guidance exposes a WinUI-specific blind spot — catch-up.** Roman Kamushken, Setproduct, November 1: <https://www.setproduct.com/blog/agent-desktop-use-cases>. The article outlines accessibility audits, smoke tests and release gates using Vercel Labs' agent-desktop, but explicitly says its examples were **not executed** on the author's machine. More useful than the enthusiasm is the limitation corroborated by the tool's Windows documentation: its menu detector covers Win32/WPF/Chromium, **not WinUI 3 or MSIX hosts**. A “no menu” result therefore does not prove your app has none. Original tool documentation: <https://agent-browser.dev/desktop/platforms/windows>.

## News/releases

- **Windows App SDK 2.6.5 ships, with a backdrop trade-off.** Microsoft release dated November 2; GitHub publication November 2, 19:18 PST: <https://github.com/microsoft/WindowsAppSDK/releases/tag/v2.6.5>. Official notes list repairs for multi-adapter/multi-monitor rendering corruption, an `E_NOINTERFACE` crash when System Composition Engine interfaces are unavailable, unexpectedly transparent Windows 10 backgrounds/GDI controls, and `E_NOTIMPL` extension-registration metadata that could prevent packaged-app installation. Crucially, Microsoft **reverted 2.6.4's system-backdrop change**: backdrops for content islands and XAML windows are unsupported with the System Composition Engine in this release. Test that combination explicitly; this is not an unqualified visual upgrade. These are shipped release-note claims, not our own test results. Notes: <https://learn.microsoft.com/en-us/windows/apps/windows-app-sdk/release-notes/windows-app-sdk-2-0?pivots=stable#version-265>.

## microsoft-ui-xaml — past 24 hours

Exact window: **November 2, 2026, 08:30 PST → November 3, 2026, 08:30 PST**. Direct API checks inspected 29 updated issues and all 647 Discussion trees, including comment/reply pagination. No new Discussion posts, comments or replies were found in this window. The following are issue-thread updates; older threads are included for new evidence, not recycled headlines.

- **Window dragging improves; the top border still needs testing.** Issue #12471, new comments November 2–3 Pacific: <https://github.com/microsoft/microsoft-ui-xaml/issues/12471#issuecomment-6602570955>. Two users, including the original reporter, say 2.6.5 fixes the 2.6.4 dragging regression. The reporter also says the broken top border returns with `ExtendsContentIntoTitleBar=true`. Useful upgrade evidence, but not a clean bill of health for custom window chrome.

- **Multi-GPU glyph corruption: encouraging recovery, with confounders.** Issue #12434, new November 2 PST observation: <https://github.com/microsoft/microsoft-ui-xaml/issues/12434#issuecomment-6592734145>. A five-monitor AMD/NVIDIA/DisplayLink user can no longer reproduce the problem and verified that Notepad actually loads runtime 2.6.5. Existing GPU registry overrides remained and the machine had restarted; they did not test immediately before updating. This aligns with the release's rendering repair, but does not isolate its cause or prove every affected configuration is fixed.

- **Custom TitleBar leaks: the old reset workaround can itself crash.** Issue #12210, new November 2 PST measurements: <https://github.com/microsoft/microsoft-ui-xaml/issues/12210#issuecomment-6590971810>. A Rust/windows-reactor developer on 2.6.4 reports roughly 22 GDI objects, 27 handles and 0.87 MB retained per closed custom-titlebar window, versus a nearly flat control. Clearing `SetTitleBar` did not eliminate it; `ResetToDefault` fail-fasted in `Microsoft.UI.Input.dll`, even after clearing the title bar. These are user measurements, not a confirmed framework diagnosis, but enough reason not to prescribe that workaround universally.

- **LinedFlowLayout crash now has a timer-lifetime lead.** Issue #12495, new November 2 PST investigation: <https://github.com/microsoft/microsoft-ui-xaml/issues/12495#issuecomment-6590602178>. The reporter says WinDbg time-travel debugging shows a queued `DispatcherTimer.Tick` firing after the native layout is freed, then accessing `InvalidateMeasureAsync`. That strengthens the earlier recreation/GC crash report, but the proposed lifetime-safe handling is not an implemented or validated fix.

- **TableView accessibility selection correction merged.** Issue #12448, closed November 3 at 08:17 PST: <https://github.com/microsoft/microsoft-ui-xaml/issues/12448>. Merged PR #12484 makes UI Automation `AddToSelection` fail appropriately when another row is selected in single-select mode, rather than silently replacing it; it also handles disabled selection and improves keyboard focus at table edges. Source/tests exist, but no available package was established to contain this change: <https://github.com/microsoft/microsoft-ui-xaml/pull/12484>.
