## Community experience

- **MSIX build failure gains an explanation—and a lighter workaround to try.** WindowsAppSDK issue, opened October 4; new reply October 5, 11:57 a.m. PDT. Updating BuildTools.MSIX to `1.7.260930100` can leave Visual Studio holding the old task DLL while loading new targets, producing the unsupported `UseSharedPriExpansionCache` parameter error. Contributor guimafelipe explains the mismatch and suspects Native AOT is incidental; the reporter’s cache cleanup worked, while simply restarting Visual Studio is a suggested—not verified—alternative. The issue was closed “by design,” not resolved by a newly shipped fix. <https://github.com/microsoft/WindowsAppSDK/issues/6841#issuecomment-6001071780>

- **Production push notifications can be blocked by provisioning, not XAML.** WindowsAppSDK issue, October 6, 2:54 a.m. PDT. An enterprise developer reports that a signed, sideloaded Flutter/MSIX application using Windows App SDK 1.7 registers successfully but cannot create a WNS channel (`0x8007139f`); they attribute the blocker to unanswered PFN-to-Entra mapping requests dating to September 16. This is shared SDK infrastructure, **not a WinUI 3 rendering bug**, but relevant to WinUI deployments: Microsoft’s existing quickstart requires mapping for packaged apps and says requests are processed weekly, so include provisioning lead time in release plans. No maintainer response or confirmed resolution was present. <https://github.com/microsoft/WindowsAppSDK/issues/6842> · Background: <https://learn.microsoft.com/en-us/windows/apps/develop/notifications/push-notifications/push-quickstart>

## microsoft-ui-xaml — past 24 hours

**Exact window:** October 5, 2026, 8:30 a.m. → October 6, 2026, 8:30 a.m. PDT. Direct API collection inspected 20 issues, excluding 35 pull requests from the issue listing, and checked comments/timelines plus Discussions metadata and selected complete comment/reply trees.

- **Long-standing `x:Bind` null-transition bugs receive a source fix.** Issues #1904 (January 2020) and #2166 (March 2020) closed immediately after PR #11732 merged October 6, 2:11 a.m. PDT. The change makes function bindings update when an argument becomes null instead of leaving stale UI, and reserves `FallbackValue` for genuinely unresolved paths. It also guards null function instances. The practical check when a package includes this change: re-test null transitions and any fallback assumptions. **Merge verified; package shipment not verified.** <https://github.com/microsoft/microsoft-ui-xaml/issues/2166> · <https://github.com/microsoft/microsoft-ui-xaml/issues/1904> · Fix: <https://github.com/microsoft/microsoft-ui-xaml/pull/11732>

- **`TransformToVisual`: the earlier non-reproduction is reversed.** Issue #12156, opened October 3; substantive new reply October 5, 12:02 p.m. PDT. dotMorten now reproduces roughly **603–628 retained native bytes per call** across SDK 2.4.0/2.5.1 after GC/finalizer/idle cycles. Measuring all process heaps—not only the default heap—exposed the difference; the minimal sample does not require a Popup, and disabling debugger support did not remove it. Reusing one transform for multiple points under unchanged geometry is suggested allocation-pressure mitigation, not a verified lifetime repair. These are contributor-reported tests, with ultimate ownership and a framework fix still unconfirmed. <https://github.com/microsoft/microsoft-ui-xaml/issues/12156#issuecomment-6001139129>

- **Normal-map lighting can point the wrong way with soft borders.** New issue #12171, October 5, 12:43 p.m. PDT. The reporter supplies a repro in SDK 2.5.1 and 2.5.4-experimental where `SceneLightingEffect` lighting changes incorrectly with brush/visual rotation and clipping under `BorderMode.Soft`. Setting `Hard` reportedly corrects lighting, but rotated sprites lose edge antialiasing and may need an alpha mask. A concrete graphics tradeoff, not a confirmed compositor fix; other GPUs/drivers and higher display scaling were not tested. <https://github.com/microsoft/microsoft-ui-xaml/issues/12171>

- **Two NavigationView crash scenarios, two different test results.** Issue #11047, opened March 27, gained two October 6 replies and a fresh demo: zhuxb711 explicitly still reproduces its navigation fast-fail in `2.5.4-experimental`. Separately, collaborator ayushjai19 reports the single-item crash in #10265, opened January 2, 2025, is not reproducible with 2.5.1. Test the matching scenario before drawing conclusions; neither comment identifies a shipped fixing change. <https://github.com/microsoft/microsoft-ui-xaml/issues/11047#issuecomment-6012339628> · <https://github.com/microsoft/microsoft-ui-xaml/issues/10265#issuecomment-6015663857>

- **TableView’s separate-DLL packaging remains a usability complaint.** Issue #12115, opened September 30; new October 6, 7:52 a.m. PDT reply. A developer challenges why experimental controls ship in a separate DLL, calling it additional friction. This adds a fresh developer objection to the existing integration discussion—not a new crash diagnosis, workaround or resolution. <https://github.com/microsoft/microsoft-ui-xaml/issues/12115#issuecomment-6018911514>
