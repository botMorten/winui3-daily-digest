## Community experience

- **ModernPaste adds faster collection switching and broader localization — catch-up.** Reddit r/windowsapps, posted October 22 PDT. The developer's v1.0.36 announcement adds remappable Selection AI shortcuts, context-aware cleanup that preserves pinned items, stickers/GIFs, and support for up to 30 languages. Faster collection switching is an author claim, not a benchmark; the visible user comments offer brief praise rather than technical validation. A concrete example of a native WinUI 3 app iterating toward full release.
  <https://www.reddit.com/r/windowsapps/comments/1xcz3gx/modernpaste_a_native_winui_3_clipboard_manager/>

- **SumaFile combines an unpackaged WinUI 3 frontend with Rust — catch-up.** Reddit r/foss, October 21 PDT; v1.0.1 released October 20. Its repository documents a Rust filesystem service over named-pipe JSON-RPC, with NSIS, MSI and portable distribution; historical Svelte/Tauri code is not the current shipping UI. One commenter questioned feature bloat, and the author said extras can be disabled. Useful adoption evidence and an architecture to inspect—not independently validated responsiveness or file-operation safety.
  <https://www.reddit.com/r/foss/comments/1xc56uv/sumafile_an_mitlicensed_windows_file_manager/>
  <https://github.com/conniecombs/SumaFile/releases/tag/v1.0.1>

- **Dispatcher accepts work but allegedly stops executing it after standby.** WindowsAppSDK issue #6797, opened September 24; new report October 24. A different contributor describes a windowed, packaged 2.5.1 app whose watchdog keeps running and Win32 window remains responsive, while `TryEnqueue` returns true without callbacks executing. Unlike the original windowless package-update reproduction, no servicing was underway. Treat this as a distinct diagnostic report: no common root cause, supported recovery, or maintainer-confirmed fix was established.
  <https://github.com/microsoft/WindowsAppSDK/issues/6797#issuecomment-6384920686>

- **Window placement: developers question which API is actually being documented.** WindowsAppSDK issue #5896, opened October 2025; three new comments October 23. A contributor pointed to an open WinUI `Window` placement-persistence specification, but the requester noted that the issue concerns experimental `AppWindow` APIs in a different layer. Practical implication: do not mistake the linked specification for documentation or a stable-release commitment covering every existing placement API.
  <https://github.com/microsoft/WindowsAppSDK/issues/5896#issuecomment-6368803557>

## microsoft-ui-xaml — past 24 hours

**Exact window: October 23, 2026, 08:30:00 → October 24, 2026, 08:30:00 PDT.** Both Issues and Discussions were directly inspected, including older threads with fresh activity.

- **AOT ItemsSource errors become actionable — Issue #11248.** Opened July 17; on October 23, dotMorten explained the closure after PR #12335 merged. The source change names the required collection interfaces instead of leaving an opaque invalid-argument failure. It improves diagnostics, not generation of missing AOT interop; the earlier CSWinRT/configuration advice is not new today. **Merged source, no verified package shipment.**
  <https://github.com/microsoft/microsoft-ui-xaml/issues/11248#issuecomment-6375533830>

- **Acrylic workaround demonstrated across more controls — Discussion #12377.** New October 23. HO-COOH showed light/dark examples across 13 named controls and a `ComboBoxHelper.AcrylicWorkaround` switch in the community WinUIEssential package. This expands the previously covered caption-tooltip story into broader control-surface examples; it is not Microsoft restoring framework acrylic or evidence of a newly published package version.
  <https://github.com/microsoft/microsoft-ui-xaml/discussions/12377>

- **A keyboard-first DateTimeBox design — Issue #2380.** Opened May 2020; October 24's detailed proposal adds text/segmented input, one logical tab stop, explicit commit/cancel, localization and accessibility considerations. It distinguishes invalid typed drafts from date-arithmetic clamping—useful desktop UX detail. **Proposal only**, without maintainer acceptance or implementation commitment.
  <https://github.com/microsoft/microsoft-ui-xaml/issues/2380#issuecomment-6381363678>

- **Frame dependency injection versus navigation parameters — Issue #693.** Opened May 2019; October 23 PDT's reply argues constructor injection suits stable services, while changing navigation data belongs in `OnNavigatedTo`. It points to an existing activation-hook proposal designed to preserve Frame caching/back-stack behavior. This is fresh design discussion, not a supported new DI extension point.
  <https://github.com/microsoft/microsoft-ui-xaml/issues/693#issuecomment-6379525289>

- **Minimized previews lose titlebar coloring — Issue #11941.** Opened September 18; October 23 PDT brought another user's reproduction and titlebar-construction code: the thumbnail/animation reportedly shows a white titlebar despite navy AppWindow colors, while maximized presentation looks correct. **Additional reproduction, not a confirmed cause or fix.**
  <https://github.com/microsoft/microsoft-ui-xaml/issues/11941#issuecomment-6378865483>
