## Community experience

- **Golden Hive: hot-swappable WinUI feature modules.** Reddit r/csharp, November 13 PST; original post and project README verified. The author introduced a .NET 10/WinUI 3 shell that downloads signed modules, loads them in separate `AssemblyLoadContext`s, and advertises staged rollouts plus replacement without restarting the host. Modules pair a WinUI client with an ASP.NET Core backend; docking, a keyboard navigation wheel and workflow integration make this an interesting enterprise-app architecture example. Crucially, the author explicitly says it is **not production-battle-tested** and the WinUI side is young; treat it as a template to evaluate, not proven hot-unload reliability.
  <https://www.reddit.com/r/csharp/comments/1xvs630/i_built_a_modular_winui_3_template_where_features/>
  Code: <https://github.com/zenoxart/GoldenHiveFramework>

- **PFI: Store packaging drove PostgreSQL → SQLite migration.** Ibrahim Oulkhir, DEV Community, November 13. Personal Finance Intelligence uses a **WinUI 3 shell with FastAPI and Next.js screens**, not an entirely native WinUI interface. Its developer reports that bundling PostgreSQL ran into Store/read-only-install-folder problems; removing it reduced installed size by 155 MB and downloads by roughly a third. The useful engineering detail is the migration: write a temporary SQLite database, verify row counts, exact integer-cent totals and foreign keys, then rename it into place while retaining the original data. Those checks are safeguards, not a mathematical guarantee of every record’s correctness; the newly published v0.5.1 also adds “Test a backup” without restoring over live data.
  <https://dev.to/mrblizo/moving-a-desktop-app-from-postgresql-to-sqlite-without-losing-a-cent-58ll>
  Release: <https://github.com/MrBlizo/personal-finance-intelligence/releases/tag/v0.5.1>

- **Hejje expands its native Windows fitness companion.** Reddit r/windowsapps, November 13 PST. The developer reports a WinUI 3/Windows App SDK update for x64 and ARM64, with activity maps and charts, workout logging, training plans, and an always-on-top picture-in-picture workout window. It remains a **phone-account companion**: GPS activities are recorded on the phone, rather than making Windows a standalone tracker. The author describes encrypted local storage and on-device assistance; those security properties were not independently audited. This is a concrete native-app adoption example, with ARM64 feedback specifically requested—not evidence of broader community sentiment.
  <https://www.reddit.com/r/windowsapps/comments/1xvwn4g/i_made_a_native_winui_3_fitness_app_see_your_runs/>
  Product/Store links: <https://hejje.app/> · <https://apps.microsoft.com/detail/9NQZJD7S5B4Z>

## News/releases

- **RHI 2.9.3 ships an adaptive overlay; 2.9.4 fixes update reporting.** RankFTW/RHI, November 13–14. The project’s tagged source confirms WinUI usage. Version 2.9.3 adds a game-library overlay with one-, two- or three-column layouts, independent scrolling, keyboard/controller activation, and colour-blind-friendly themes; its notes also credit a contributor for identifying the cause of buttons briefly flashing with Windows animations enabled. The overlay supports borderless/windowed games, not true exclusive fullscreen. This morning’s 2.9.4 fixes misleading “up to date” results after GitHub rate limiting and handling of rejected tokens—useful reminders that an updater’s failure state must not masquerade as success. These are **app release claims**, not a newly shipped WinUI runtime fix.

## microsoft-ui-xaml — past 24 hours

**Exact window:** November 13, 08:30 → November 14, 08:30 PST. Both Issues and GitHub Discussions were inspected directly, including older threads with fresh activity.

- **Issue: theme-resource binding reaches a stable source branch.** Tracking issue opened September 1; **new November 13 activity:** contributor gegao18 said `FrameworkElement.SetThemeResourceBinding` was “checked into 2.0-stable” and closed the issue. This moves the API’s stabilization work forward, but the comment establishes a **source-branch check-in**, not availability in a released stable package. Verify your target SDK’s API surface before depending on it.
  <https://github.com/microsoft/microsoft-ui-xaml/issues/11753#issuecomment-6861462961>

- **Issue: a 2022 static `x:Bind`/DataTemplate bug gets a draft compiler fix.** **New November 13 PST activity:** the old issue was linked to Microsoft member evelynwu-msft’s draft PR addressing item-independent bindings when template content is null, with changes for generated C# and C++/WinRT code. This matters when static bindings inside an otherwise empty template fail to initialize; it is **open, draft and unmerged**, and a compiler fix would require rebuilding affected apps—not merely installing a runtime update.
  <https://github.com/microsoft/microsoft-ui-xaml/issues/7810>
  Proposal: <https://github.com/microsoft/microsoft-ui-xaml/pull/12666>

- **Issue: TableView users want spreadsheet-friendly clipboard export.** **New November 13 proposal:** Shift+Click multi-row selection plus Ctrl+C exporting table-shaped data for spreadsheet pasting. It highlights a concrete line-of-business expectation for the new control. Only automated triage followed; **no maintainer acceptance or implementation is established**.
  <https://github.com/microsoft/microsoft-ui-xaml/issues/12662>
