## News/releases

- **WinUI unit-test templates gain the MTP workflow in source.** Microsoft WindowsAppSDK PR #6885, merged November 5. The change adds Microsoft.Testing.Platform and packaged/unpackaged choices, enabling async UI tests and AOT-oriented workflows. Unlike an ordinary STA test, these tests use the app's real UI dispatcher. In the linked XAML issue, dotMorten confirms the template work is completed but pending release—material progress beyond the previously covered proposal, **not a shipped template-pack announcement**. <https://github.com/microsoft/WindowsAppSDK/pull/6885> <https://github.com/microsoft/microsoft-ui-xaml/issues/11267#issuecomment-6673663356>

- **CLI launch-profile warnings fixed—but mind the Visual Studio identity trap.** Microsoft WindowsAppSDK PR #6954, merged November 6. Packaged scaffolds regain a `Project` profile so `dotnet run` stops warning that no usable profile exists; WinApp still supplies package identity. Reactor's devtools profile now passes `--devtools app`, avoiding the bare flag's MCP-server mode. However, selecting `(Unpackaged)` for a packaged project in Visual Studio still launches without identity and can fail with `REGDB_E_CLASSNOTREG`: keep `(Package)` there. The 0.0.8-alpha version bump is merged, but NuGet still showed 0.0.7-alpha at collection. <https://github.com/microsoft/WindowsAppSDK/pull/6954> <https://www.nuget.org/packages/Microsoft.WindowsAppSDK.WinUI.CSharp.Templates>

## microsoft-ui-xaml — past 24 hours

**Exact window:** November 5, 2026, 08:30 PST–November 6, 2026, 08:30 PST. These are new developments in existing **Issues**, not newly opened threads; the testing update above also belongs to this activity window.

- **NativeAOT reentrancy: another developer supplies a concrete crash stack.** Issue #11099, opened May 12; new November 6 comments. A developer using SDK 2.6.5/.NET 10.0.14 NativeAOT traces wrapper-table locking during `VisualStateManager` argument marshaling into nested XAML timer dispatch and fail-fast. Timer deferral is suggested, not accepted or shipped. Another reporter explicitly says 94 clean navigation clicks did **not** reproduce the contention or test their mitigation: a clean short run is not proof of resolution. <https://github.com/microsoft/microsoft-ui-xaml/issues/11099#issuecomment-6687927089>

- **Expander-associated exception fix lands, explicitly unreleased.** Issue #11253, opened July 19; November 5 update. PR #12563 is merged, and JesseCol confirms it is on `main`, not in a release. Implementation notes correct the headline's implication: `UnhandledException` already ran; stale native error context could make a later unhandled async exception fail-fast incorrectly. This fixes that error-context handling, not arbitrary unsafe exception recovery. <https://github.com/microsoft/microsoft-ui-xaml/issues/11253#issuecomment-6673227454> <https://github.com/microsoft/microsoft-ui-xaml/pull/12563>

- **TableView gets two practical source fixes.** Issues #12446/#12442, opened October 28; fixes merged November 5. One addresses Star-column overflow after manual resizing followed by `MaxWidth` changes; the other restores the correct cell's focus when dismissing a same-row context menu with Esc. Relevant to resizable business grids and keyboard navigation. Both merges are verified; package availability is not. <https://github.com/microsoft/microsoft-ui-xaml/issues/12446> <https://github.com/microsoft/microsoft-ui-xaml/issues/12442>

- **Bitmap “DPI shrink” receives a bounded workaround.** Issue #8733, opened August 10, 2023; contributor explanation November 5. Their repro attributes shrinking to a 4096-pixel-per-side rendering cap: larger scaled content is reduced, changing the bitmap's natural display size. Explicitly set the destination `Image.Width/Height` to the captured extent—not potentially zero `Canvas.ActualWidth/Height`. This restores display size, **not lost detail**; separate smaller captures are suggested for sharpness. A contributor diagnosis/workaround, not a newly shipped DPI fix. <https://github.com/microsoft/microsoft-ui-xaml/issues/8733#issuecomment-6677978248>

- **Chart accessibility progress has several different statuses.** Issues opened November 4–5; new updates November 5–6. A contributor reports fixes/tests for descending-sort arrow navigation, secondary-window theming and out-of-range labels in internal ADO PRs; their merge status could not be independently verified. Public live-region announcement PR #12581 remains **open**. Fixed-spacing label disappearance and RTL text mirroring explicitly have no fix/PR yet. Useful progress, not six shipped fixes. <https://github.com/microsoft/microsoft-ui-xaml/issues/12557#issuecomment-6680115620> <https://github.com/microsoft/microsoft-ui-xaml/issues/12546> <https://github.com/microsoft/microsoft-ui-xaml/issues/12545> <https://github.com/microsoft/microsoft-ui-xaml/pull/12581> <https://github.com/microsoft/microsoft-ui-xaml/issues/12572> <https://github.com/microsoft/microsoft-ui-xaml/issues/12570>
