## Community experience

- **Why `.1` target-framework versions break current WinUI builds — new maintainer explanation.** WindowsAppSDK issue opened October 13; new response October 15: <https://github.com/microsoft/WindowsAppSDK/issues/6859#issuecomment-6202112708>. A Microsoft member explains that Windows TFMs ending in `.1` select the rewritten **CsWinRT 3.0 projections**, still in preview; there is not yet a compatible Windows App SDK package. This supplies the missing reason behind the previously reported `.0`-works/`.1`-fails experiment: keep using the supported `.0` TFMs for current development. It is not a blanket .NET 10 incompatibility, and no new fixing SDK package was announced.

- **Push-channel failure reopened after mistaken duplicate classification.** WindowsAppSDK issue originally October 6; new maintainer response October 15: <https://github.com/microsoft/WindowsAppSDK/issues/6842#issuecomment-6201554762>. A Microsoft member acknowledges that the reporter’s `CreateChannelAsync`/`0x8007139f` failure is **not the same** as the case it had been grouped with, reopens the original issue and closes its follow-up duplicate. The real-world app is Flutter using Windows App SDK 1.7 in enterprise-sideloaded MSIX—not WinUI UI adoption—but its shared SDK push/deployment problem is relevant to notification-dependent Windows apps. This is corrected triage, not a diagnosed root cause, completed PFN mapping or verified workaround.

## microsoft-ui-xaml — past 24 hours

**Exact window:** October 15, 2026, 08:30 PDT → October 16, 2026, 08:30 PDT. Direct API inspection covered 10 issues and all 643 accessible Discussions, including older comments/replies; pagination and count-integrity checks completed.

- **NavigationView: reporter supplies a workaround and closes yesterday’s selection issue.** New late-October 15 PDT response (October 16 UTC): <https://github.com/microsoft/microsoft-ui-xaml/issues/12303#issuecomment-6209940085>. The reporter says resetting the relevant item’s `IsExpanded` to `false` when the left pane closes resolved the stale parent-selection state, then closed the issue. This is a useful new application-side workaround—not a merged framework fix or package release. Test it against your own hierarchical navigation behavior.

- **New ItemCollection owner-lifetime repro—distinct from yesterday’s generator crash.** Opened October 16: <https://github.com/microsoft/microsoft-ui-xaml/issues/12317>. A C++/WinRT repro retains `ItemsControl.Items`, releases its owner and verifies destruction with a weak reference. The surviving collection reportedly still answers `Size()`, while `Clear()` and `Append()` return `E_UNEXPECTED` (`0x8000FFFF`). The reporter connects this existing public-API behavior to the separate proposal to make ItemCollection publicly constructible. Reported against 2.5.1; no human-confirmed fix is present, and this is an HRESULT failure, not a demonstrated access violation.

- **New experimental TableView resize-cursor report.** Opened October 15: <https://github.com/microsoft/microsoft-ui-xaml/issues/12310>. Resizing a column in the WinUI Gallery’s basic TableView example reportedly leaves the default pointer instead of showing a resize cursor. The report includes visual comparisons and identifies `2.5.4-experimental` on Windows 11 25H2. Relevant when evaluating the experimental control’s UX; no human-confirmed workaround or fix was found.

- **InkCanvas Discussion gets an experimental-package pointer—not a new release.** New October 16 reply to the older availability question: <https://github.com/microsoft/microsoft-ui-xaml/discussions/7426#discussioncomment-18970853>. A community member points to `Microsoft.WindowsAppSDK/2.5.4-experimental` and says much of the WinUI 2 inking functionality is available to try. Existing [experimental release notes](<https://github.com/microsoft/microsoft-ui-xaml/releases/tag/winui3/release/2.5.4-experimental>) independently document inking/custom-drying/InkToolbar updates, but the commenter’s feature-parity assessment is not independently validated. The package predates this window; no stable-release arrival is established by this reply.
