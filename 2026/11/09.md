## Community experience

- **First launch after MSIX installation: seconds before managed code.** WindowsAppSDK issue, **Nov 9**: a developer using **SDK 2.1.3, .NET 8, x64** reports 3.1–4.2 seconds to show a window after install/redeployment, versus roughly 0.21–0.23 seconds on the next launch; their instrumentation attributes 2.1–2.9 seconds to the pre-managed segment. Useful lesson: measure fresh-install/redeploy startup separately from warm launches. This is one application's report—not a confirmed platform root cause, latest-SDK regression or tested fix; a blank-template reproduction is still missing. <https://github.com/microsoft/WindowsAppSDK/issues/6963>

- **Missing 2.6.5 item templates: now a concrete workaround.** **Update Nov 8–9** to the Nov 7 report: contributor dotMorten explains that templates ship with Visual Studio, not the SDK NuGet packages. The reporter says adding `<ProjectCapability Include="WindowsAppSdk" />` restores template discovery while retaining a WinUI-only dependency rather than pulling unwanted AI/ML packages into self-contained deployment. Treat this as a reporter-tested project workaround, not a shipped SDK repair. <https://github.com/microsoft/WindowsAppSDK/issues/6960#issuecomment-6735939779>

- **Fluent Weather ships a WinUI 3 rebuild—with an architecture caveat.** Reddit/r/windowsapps, **Nov 7 Pacific; missed-coverage catch-up**: its author reports native controls, acrylic and a tile-based weather dashboard, but the redesign currently targets **Windows 11 ARM64 only**; x64 retains the previous version, and adding a city through current location is temporarily disabled. In the inspected comments, another WinUI developer suggests padding and title-bar/search changes; the author says revisions are underway. Real adoption, plus the practical reality that a Store update needn't mean feature parity across architectures. <https://www.reddit.com/r/windowsapps/comments/1xqsyvf/fluent_weather_winui_3_native_fluent_design_and/>

- **HOOKS adopts the multi-GPU rendering fix.** Reddit/r/windowsapps, **Nov 6; catch-up**: the developer announces Store release **2.1.20**, including a radial launcher, refreshed game artwork and Windows App SDK **2.6.5** to address corrupted text/icons on multi-monitor or multi-GPU systems. This is downstream adoption of the platform fix previously covered here, not another SDK release or independent benchmark; the author also flags a slower-at-login tradeoff from switching to standard Windows startup registration. <https://www.reddit.com/r/windowsapps/comments/1xpqma5/hooks/>

## microsoft-ui-xaml — past 24 hours

**Exact window:** November 8, 2026, 08:30 PST → November 9, 2026, 08:30 PST. Direct API inspection covered six updated issues, excluding pull requests, and all 649 current Discussion trees. **No in-window Discussion activity was verified.** The two new issue comments were automated triage, not human maintainer responses.

- **Image decoding/cache lifetime crash — new issue Nov 9.** The reporter supplies native stacks and an unpackaged .NET 10 repro, claiming crashes on both 1.8.251106002 and 2.6.5 when images are destroyed while decoding is queued. Reusing one `BitmapImage` per URI reportedly survived three 20-minute runs. This is a useful candidate workaround for image-heavy apps, **not an established root cause or confirmed framework fix**; the only reply is AI triage. <https://github.com/microsoft/microsoft-ui-xaml/issues/12615>

- **Grouped TableViewSource retention — Oct 29 issue, newly resolved in source Nov 9.** Maintainer hiteshkrmsft merged the repair and closed the issue during this window. Tracker-aware shaping delegates break native/managed ownership cycles; the author reports retained sources dropping from 22 to 2 after repeated page visits, with approximately 4.5% reshape overhead. Custom-sort-comparer cycles remain a follow-up. **Source merged; package availability unverified.** <https://github.com/microsoft/microsoft-ui-xaml/issues/12474> <https://github.com/microsoft/microsoft-ui-xaml/pull/12585>

- **TableView accessibility scroll-to-end — Oct 28 issue, merge/closure Nov 9.** The repair stabilizes the UI Automation scroll provider and retries bottom positioning as variable-height rows realize. That matters for automation clients that previously stopped short of the end; the PR explicitly retains a limitation where an outer nested ScrollViewer can settle near 95%. Regression tests accompany the merged change, but this is **not a verified released fix**. <https://github.com/microsoft/microsoft-ui-xaml/issues/12449> <https://github.com/microsoft/microsoft-ui-xaml/pull/12593>

- **Leaf-row context menus — Oct 29 issue, merge/closure Nov 9.** The invisible hierarchy-chevron gutter no longer intercepts clicks on leaf rows, allowing the leading cell's context menu to receive them. Expandable-row chevrons deliberately keep the row menu; tests cover recycling and leaf/expandable transitions. **Merged source only**, with no new package shipment established. <https://github.com/microsoft/microsoft-ui-xaml/issues/12470> <https://github.com/microsoft/microsoft-ui-xaml/pull/12592>
