## News/releases

- **A direct API for app-versus-system light/dark settings is proposed.** — WindowsAppSDK specification, October 22. `ColorModeSettings` would expose separate app and system color modes plus change notification, targeting the awkward gap between XAML themes, derived `UISettings` colors, and undocumented registry values—particularly useful for matching tray icons to the taskbar. The specification treats high contrast separately; this is an open API proposal, not something available in today's released SDK. <https://github.com/microsoft/WindowsAppSDK/issues/6890>

- **AI-package IntelliSense documentation: Microsoft points to an existing package fix.** — Issue opened April 21; new maintainer response October 22. A Microsoft member closes the missing-XML-documentation report, saying the XML files are present in `Microsoft.WindowsAppSDK.AI` 2.5.5 and linking package evidence. Useful for developers missing API descriptions in editors, but this is newly confirmed coverage of an older package: NuGet dates 2.5.5 to September 16, not a new release today, and package contents were not independently unpacked here. <https://github.com/microsoft/WindowsAppSDK/issues/6423#issuecomment-6345950361> · <https://www.nuget.org/packages/Microsoft.WindowsAppSDK.AI/2.5.5>

## microsoft-ui-xaml — past 24 hours

**Exact window:** October 22, 08:30 → October 23, 08:30 PDT. Direct API inspection covered 26 updated issues, excluding 42 pull requests from issue counts, plus all 645 enabled Discussions and their comment/reply trees. The scan found 14 in-window human issue-comment activities, including edits; highlights below exclude routine triage churn.

- **NavigationView: the closed-pane fix has merged.** — Issue #7609, originally August 2022; new merge/closure October 22 PDT. PR #12325 now preserves an explicitly closed initial pane when `IsPaneOpen=false` precedes `PaneDisplayMode=Left`, while retaining runtime behavior for already-loaded controls. This advances the previously reported draft to a source fix; a follow-up draft adds re-templating tests, not another delivered product fix. No released package containing it was verified. <https://github.com/microsoft/microsoft-ui-xaml/issues/7609> · <https://github.com/microsoft/microsoft-ui-xaml/pull/12325>

- **Staggered entrance animations: another source fix lands.** — Issue #8879, originally September 2023; new merge/closure October 22. PR #12196 gives the injected visibility animation the transition duration so the reveal can run with compositor-driven motion instead of waiting on a UI-thread tick. Regression tests accompany the change, but the author notes that the exact original unstressed-video reproduction remains unconfirmed; this is not evidence that an SDK update has shipped the fix. <https://github.com/microsoft/microsoft-ui-xaml/issues/8879> · <https://github.com/microsoft/microsoft-ui-xaml/pull/12196>

- **Menu press–drag–release behavior gets renewed pushback.** — Older issues spanning 2019–2023; six new human comments from three participants across four related threads on October 22. Developers argue that selecting a menu command in one held-press gesture is basic Win32/WPF parity, while another participant cites its earlier classification as a feature request rather than a bug. A commenter offers to investigate a PR; there is no delivered fix. The practical complaint is extra clicks in desktop workflows, not merely visual polish. <https://github.com/microsoft/microsoft-ui-xaml/issues/815#issuecomment-6353196553> · <https://github.com/microsoft/microsoft-ui-xaml/issues/5600>

- **Charts discussion shifts from announcement to API/style constraints.** — Discussion #12343, opened October 20; three new replies and an edited older comment in this window. New replies question specification timing, and JohnnyWestlake says SolidColorBrush-only support prevents broader XAML-brush styling. That limitation is a participant's implementation claim, not a newly verified maintainer commitment or fix; the announcement itself is not new today. <https://github.com/microsoft/microsoft-ui-xaml/discussions/12343#discussioncomment-19148127>

- **Window/XAML trouble prompts a template-level workaround proposal.** — Issue #7305, originally July 2022; two new comments October 22–23 UTC route feedback to WindowsAppSDK #6891. The new proposal would construct `Window` in code and put the UI in `MainPage.xaml`, avoiding the problematic generated `MainWindow.xaml` pattern rather than changing Window inheritance. Another developer supports that direction, but it remains an open proposal—not an accepted or shipped template change. <https://github.com/microsoft/microsoft-ui-xaml/issues/7305> · <https://github.com/microsoft/WindowsAppSDK/issues/6891>
