## Community experience

- **Annotator pairs WinUI app windows with a native graphics overlay.** *Developer post, October 23; catch-up.* This open-source, public-beta presentation utility uses C#/.NET 10, WinUI 3 and Native AOT on x64/ARM64; its architecture separates platform-free core/workspace logic from Win32, Composition, Direct2D and Direct3D 11 overlay work. That is a useful real-world example of choosing WinUI for app UI without pretending every desktop-overlay requirement belongs in XAML; the author lists Store distribution, but no reader sentiment is inferred from the inaccessible comment area. Post: <https://www.reddit.com/r/windowsapps/comments/1xd8nmm/annotator_free_opensource_screen_annotation_for/> · Architecture: <https://github.com/dorlugasigal/annotator/blob/main/docs/architecture.md>

- **DeskBox 1.5.9 documents the unglamorous work behind desktop widgets.** *Project release, labeled October 23; GitHub publication October 22 PDT; catch-up.* The WinUI 3 organizer's release notes attribute a Windows 11 25H2 submenu crash to a removed font file with a surviving registration, alongside display-topology and drag/drop repairs. Its published x64/ARM64 Native AOT installers bundle a private Windows App Runtime for offline installation; they are explicitly unsigned, and the available Store-upload artifact does not establish Store approval. <https://github.com/Tianyu199509/DeskBox/releases/tag/v1.5.9>

- **Reactor follow-up answers clarify incremental adoption and state ownership.** *Original article October 21; missed author replies October 22, reader follow-up October 23.* Beyond the announcement already covered, Microsoft's Alexandre Chohfi explains that Reactor/XAML interoperate in both directions, shared selection belongs in the nearest common parent, and Context supplies dependency injection; he also points to state-preserving hot reload and a rough, build-from-source Visual Studio preview extension. One reader says coexistence changes their willingness to try it—an individual response, not broad adoption evidence; Reactor remains experimental, without API guarantees. Technical answer: <https://devblogs.microsoft.com/ifdef-windows/microsoft-ui-reactor-a-c-first-way-to-build-winui-apps/#comment-203> · Interop: <https://devblogs.microsoft.com/ifdef-windows/microsoft-ui-reactor-a-c-first-way-to-build-winui-apps/#comment-201>

## News/releases

- **PowerToys 0.102 actually ships two more WinUI 3 migrations.** *Microsoft release v0.102.2933.0, October 21; catch-up.* Color Picker's picking overlay, editor and magnifier, plus Text Extractor's overlays, move to WinUI 3 while preserving existing workflows, shortcuts and settings. This is published, non-prerelease adoption evidence—not another roadmap promise—and the source-linked changes offer migration examples; app-specific repairs in the release should not be mistaken for framework-wide fixes. <https://github.com/microsoft/PowerToys/releases/tag/v0.102.2933.0>

- **Issue #12386 — ItemsView throws after rebinding and deleting selected items.** Opened October 24: the reporter supplies a two-string repro in which the second valid `RemoveAt(0)` empties the collection, then throws during WinUI collection-change handling, claiming 20/20 reproduction with both tested package configurations. A new human response offers investigation but explicitly leaves root cause unconfirmed; test deletion after replacing `ItemsSource` if your app uses multiselection, and do not treat the proposed selection-model explanation as a verified fix. <https://github.com/microsoft/microsoft-ui-xaml/issues/12386>
