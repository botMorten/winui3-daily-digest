## Community experience

- **RimestDB: WinUI 3 for a full database-client workflow.** Reddit r/windowsapps, **October 29**. The developer introduces a Windows-only WinUI 3/.NET client supporting PostgreSQL, SQL Server, MySQL/MariaDB, Oracle and SQLite, with editable result grids, per-tab connections, manual commit/rollback, SSH tunnels and Excel export. The product site corroborates the stack and features; “fast/lightweight” remains the author’s claim, not an independent benchmark, and the visible reply offers to try it rather than validating it. This is a concrete commercial, data-heavy adoption example, with a seven-day trial—not evidence that WinUI’s grid/performance problems are universally solved.
  <https://www.reddit.com/r/windowsapps/comments/1xiv5vs/i_built_a_native_windows_database_client_winui_3/> · <https://db.rimest.com/>

- **UI-test density remains a practical deployment cost.** Reddit r/dotnet, **October 29; newly verified catch-up**, with an author reply inside today’s window. A team shipping WPF/WinUI 3 MSIX apps describes physical hosts running three to four full Windows VMs each, and reports that alternate desktops do not provide the real-input behavior needed for drag, hover and tab tear-off tests. A commenter recommends view-model tests, stable AutomationIds and a small UI smoke suite; the author responds that they already test view models and still need visual/focus assertions. No proven lightweight parallel-desktop solution emerges from the inspected exchange.
  <https://www.reddit.com/r/dotnet/comments/1xikpgp/how_do_you_scale_ui_automation_for_wpf_winui_3/>

- **Arabic shaping: a detailed DWriteCore 2.6.4 repro.** WindowsAppSDK issue, **October 29**. The reporter provides tiny fonts and a standalone C++ repro in which Combining Grapheme Joiner disrupts Arabic joining and a substitution loses a visible glyph despite successful API calls. This is adjacent text-stack evidence relevant to multilingual Windows apps, not a demonstrated WinUI-control defect; removing CGJ is a diagnostic control, not a safe production workaround. No maintainer confirmation or earlier-version comparison establishes a newly introduced 2.6.4 regression.
  <https://github.com/microsoft/WindowsAppSDK/issues/6913>

- **Update to yesterday’s localization story: Microsoft tracks stale template build tools.** WindowsAppSDK, **October 29**. A repository member opens a dedicated issue to update outdated MSIXBuildTools in templates and acknowledges the earlier report. The practical lesson remains to inspect resolved packaging-tool dependencies rather than assume the app runtime caused missing bundle languages. This is new acknowledgement/tracking of the same problem—not a second independent bug or a shipped fix.
  <https://github.com/microsoft/WindowsAppSDK/issues/6912> · <https://github.com/microsoft/WindowsAppSDK/issues/5817#issuecomment-6503925157>

## News/releases

- **.NET 10+ WinUI templates gain an SDK 10+ constraint—in source.** WindowsAppSDK PR, **merged October 29**. The change raises SDK eligibility for blank, library, MVVM, TabView and unit-test templates and adds the missing navigation-template constraint. It prevents inappropriate template selection; it does not raise every WinUI application’s runtime requirement. No newly published template package was verified. Official release checks found no SDK release newer than the already-covered stable 2.6.4.
  <https://github.com/microsoft/WindowsAppSDK/pull/6914>

- **Cross-adapter corruption is not confined to Intel/NVIDIA laptops.** Issue **#12434**, opened October 28; **new October 29 report** describes dual RTX 5070 Ti cards and corruption in Notepad/3CX across displays attached to different GPUs, with both apps depending on runtime 2.6.4. Explicit GPU preference plus a full app restart reportedly helps that system. This broadens reproduction topology; it is neither a universal workaround nor proof that 2.6.4 introduced the defect.
  <https://github.com/microsoft/microsoft-ui-xaml/issues/12434#issuecomment-6505214598>

- **Windows 10 border issue moves from non-repro to reproduction.** Issue **#12471**, opened October 29. After comparison builds were supplied, JesseCol’s **October 29, 19:09 PDT** response confirms the **top-border-color** problem and says investigation is underway. That confirmation should not be expanded to every dragging/resizing symptom, a root cause or a fixed release.
  <https://github.com/microsoft/microsoft-ui-xaml/issues/12471#issuecomment-6513222545>

- **Graphics-device-release proposal closes in favor of shutdown/restart work.** Issue **#11741**, opened September 1; **October 29 closure** points to PR #11982. That PR merged October 13—not today—and addresses restart validity/reference-cycle behavior. Its explicit retention of Application/metadata until process teardown makes “all allocations reclaimed” too strong; no package shipment was established.
  <https://github.com/microsoft/microsoft-ui-xaml/issues/11741#issuecomment-6505066843>

- **Combined DateTimePicker proposal gets a clearer keyboard-first scope.** Issue **#2380**, opened May 2020; **October 29, 23:24 PDT clarification** narrows the proposal to typing/editing date-time fields without opening a popup, alongside pointer-friendly alternatives. The author describes a developing proof of concept; this is community design progress, not an accepted or shipped control.
  <https://github.com/microsoft/microsoft-ui-xaml/issues/2380#issuecomment-6516452849>
