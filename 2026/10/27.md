## Community experience

- **Wintor reaches the Store, with practical distribution lessons.** GitHub, October 27 UTC/early October 27 PDT. The developer’s dated commit says Wintor 0.2.0 passed certification and is live; its Microsoft Store listing also resolves. The early-development app combines WinUI 3, .NET 10 and MonoTorrent, with an engine-independent core, tray/background seeding, x64/ARM64 support and UI Automation smoke tests—a concrete native desktop project rather than another framework pitch. A preceding commit records rejection of the keyword “windows 11 torrent” under Store policy 10.1.3, replaced with “free torrent app.” That is the author’s certification account, not a general ruling independently verified here; installation and runtime behavior were not tested. Source: <https://github.com/tarasenko-by/wintor/commit/b1f1ef97f12f6844164ac127299bdaf199d1fccc>; keyword lesson: <https://github.com/tarasenko-by/wintor/commit/59e43c9cbf1ff93e3a3ca3cb7010568f98e2759d>.

- **NativeAOT publishing can silently omit the MSIX.** WindowsAppSDK issue #6897, opened October 26. A detailed WinUI 3/Windows App SDK 2.5.1 repro attributes two failures to .NET 11’s optimized publish path: missing references during XAML compilation, then skipped PRI/package generation because `PrepareForRun` never executes. With stale build output present, the reporter gets exit code zero but no `.msix`; their control using `-p:UseOptimizedPublish=false` produces a package. This is reporter-tested mitigation, not a maintainer-confirmed or shipped fix. Practical implication: verify the actual package artifact in CI, not just publish’s exit code. <https://github.com/microsoft/WindowsAppSDK/issues/6897>

- **Correction: experimental AppWindow placement documentation is unresolved.** WindowsAppSDK #5896, originally October 8, 2025; new team response October 26. Lauren Ciha reopened the issue and apologized: the earlier closure mistook a spec on a closed PR for documentation merged into main. This materially updates the closure covered previously; it does **not** establish a stable release plan. Developers evaluating placement persistence should distinguish these AppWindow APIs from the separate WinUI Window work. <https://github.com/microsoft/WindowsAppSDK/issues/5896#issuecomment-6424198201>

## microsoft-ui-xaml — past 24 hours

**Exact window: October 26, 08:30–October 27, 08:30 PDT.** Both Issues and Discussions were inspected directly through GitHub APIs, including older threads’ comments/replies.

- **NavigationView-related fixes move from proposals into merged source.** Older issues #9331 (February 2024) and #8283 (March 2023) closed October 26 PDT after associated PRs merged. The first repairs stale ScrollViewer pointer bookkeeping that could make a later ToggleSwitch interaction steal focus; the second preserves flyout-owner resource lookup so overflow selection indicators honor scoped colors and theme changes. The focus repair is a material update to the previously reported open proposal. **Source merges verified; released package availability not verified.** <https://github.com/microsoft/microsoft-ui-xaml/issues/9331> · <https://github.com/microsoft/microsoft-ui-xaml/issues/8283>

- **TableView: clearer resize feedback and border fixes confirmed for the next experimental release.** New October 27 contributor responses close October’s #12310 and #12353, confirming main-branch fixes for the resize cursor and doubled right border. A final Star-width column will not show a right-edge resize gripper; fixed/Auto columns retain theirs. These comments confirm earlier source changes, not new merges today; the larger resize-hit-target request is not established as implemented. <https://github.com/microsoft/microsoft-ui-xaml/issues/12310#issuecomment-6440068933> · <https://github.com/microsoft/microsoft-ui-xaml/issues/12353#issuecomment-6440030413>

- **New source-build repro explains an empty-registration launch failure.** Issue #12410, opened October 26 PDT, traces a three-build sequence in which stale `package.appxfragment` timestamps trigger regeneration while `FillExtensions` is skipped, leaving empty registration extensions and “ClassFactory cannot supply requested class.” This adds a distinct repro to yesterday’s related build-timestamp coverage. Associated PR #12398 remains open: useful evidence for framework contributors, not proof a released SDK regressed or the compiler bug is fixed. <https://github.com/microsoft/microsoft-ui-xaml/issues/12410>

- **NavigationView retains a narrowly scoped selection-indicator gap.** New #12411, October 27, reports that the first Left→Top switch loses a collapsed parent’s selection pill with `MenuItemsSource`/`MenuItemTemplate`; another switch or new selection restores it. Markup-defined `MenuItems` are reportedly unaffected. The related open repair explicitly leaves this case unresolved—no successful fix verified. <https://github.com/microsoft/microsoft-ui-xaml/issues/12411>
