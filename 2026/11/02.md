## News/releases

- **MVVM template proposal addresses WinRT marshalling warnings** — WindowsAppSDK contributor PR, November 1. The patch replaces `[ObservableProperty]` fields with public partial properties to address MVVMTK0045 and allow CsWinRT to generate the required marshalling code. Its author reports warning-free Debug builds on x64, x86 and ARM64: a concrete pattern to evaluate in affected projects, **not an independently tested or shipped template fix**; the PR is open and unmerged. <https://github.com/microsoft/WindowsAppSDK/pull/6923>

- **Remembering Visual Studio scaffolding choices** — WindowsAppSDK contributor PR, November 1. A separate proposal shares persisted framework, minimum-Windows-version and packaging selections across templates; text fields such as publisher are excluded. This is a modest project-creation improvement under review, not a released Visual Studio feature or something existing apps need to adopt. <https://github.com/microsoft/WindowsAppSDK/pull/6927>

## microsoft-ui-xaml — past 24 hours

**Exact window:** November 1, 08:30 PST → November 2, 08:30 PST (16:30–16:30 UTC). Directly inspected 20 updated issues, excluding 36 PRs from issue candidates, plus all 647 accessible Discussions and their comment/reply trees. The window contained 15 human issue comments, one new Discussion, three Discussion comments and two replies; these are activity counts, not measures of popularity.

- **Multi-GPU glyph corruption: downgrade tests need runtime verification** — **Issue #12434**, opened October 28; new comments November 2 UTC. Fresh packaged-app tests report clean rendering with the actual 2.5.1 runtime and corruption with 2.6.4, explaining that rebuilding against an older SDK can still load the newest installed framework. Additional dual-GPU/DisplayLink reports describe primary-display interactions. Practical lesson: inspect the loaded `Microsoft.UI.Xaml.dll` before drawing version conclusions; neither a universal workaround nor a confirmed root cause is established. <https://github.com/microsoft/microsoft-ui-xaml/issues/12434#issuecomment-6567125934>

- **Missing ink telemetry acknowledged** — **Discussion #12264**, opened October 13; new responses November 1–2 UTC. A repository member confirms a shipping-train omission and says the telemetry is coming in an upcoming experimental release—**not already available**. A contributor also confirms that ETW needs the InkCanvas `0x10000` or InkToolbar `0x4000` keyword together with Measures; a default-keyword trace alone cannot establish that telemetry is absent. <https://github.com/microsoft/microsoft-ui-xaml/discussions/12264#discussioncomment-19347042>

- **TitleBar padding: DPI units and monitor changes both matter** — **Issue #10344**, opened February 12, 2025; new reproduction November 1 UTC. A reporter using 2.6.4 describes incorrect right-side padding at 150% scaling and stale padding after moving between monitors. Their workaround updates the template's `RightPaddingColumn` using `RightInset / RasterizationScale` after Loaded and on `XamlRoot.Changed`, skipping minimized windows. This is a reporter-supplied template workaround, not a framework fix or a reproduction independently run for this digest. <https://github.com/microsoft/microsoft-ui-xaml/issues/10344#issuecomment-6565588060>

- **Reentrancy fail-fast evidence extends beyond input inertia** — **Issue #11099**, opened May 12; new report November 1 UTC. A developer classifies 52 crash dumps involving XAML's frame timer re-entering during STA lock waits, using .NET 10 and self-contained SDK 2.5.1. Spin-count experiments remain inconclusive, and the reporter asks for a supported mitigation. Treat this as stronger diagnostic evidence—not a validated production configuration change. <https://github.com/microsoft/microsoft-ui-xaml/issues/11099#issuecomment-6560734127>

- **ListView range-notification defects gain a proposed common correction** — **Issues #11254, #10235 and #9607**, originating in 2024–2026; newly cross-referenced November 2 UTC. PR #12509 proposes consistent per-item vector notifications for multi-item Add/Remove/Replace events, targeting missed range updates, selection shifts and subsequent errors. It remains **open, unmerged and unshipped**; large ranges would still incur per-item work. <https://github.com/microsoft/microsoft-ui-xaml/issues/11254> · <https://github.com/microsoft/microsoft-ui-xaml/pull/12509>

- **MenuBar wrapping gets a community template answer** — **Discussion #12502**, created and answered November 1 UTC. A custom template replaces the horizontal StackPanel with CommunityToolkit's WrapPanel while retaining named template parts; the requester confirms it meets their need. This is a community workaround rather than new built-in wrapping support—validate keyboard navigation and accessibility in the resulting app. <https://github.com/microsoft/microsoft-ui-xaml/discussions/12502#discussioncomment-19337720>
