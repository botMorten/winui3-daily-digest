## Community experience

- **Custom title bars can crash service-launched UI tests.** WindowsAppSDK issue #6955, filed November 6, describes an access violation in 2.6.5 when `ExtendsContentIntoTitleBar(true)` runs in a non-interactive window station: DirectComposition returns access denied, then the implementation reportedly dereferences a null device. The author checks `WSF_VISIBLE` through `GetUserObjectInformation` and skips title-bar extension when absent—a reported workaround, not a confirmed upstream fix. Relevant to CI agents launching apps from Windows services. <https://github.com/microsoft/WindowsAppSDK/issues/6955>

- **A 2.5 item-template fix reportedly disappeared in 2.6.** Issue #6960, filed November 7, says Visual Studio item templates are unavailable when a project references only the `.WinUI` package; the reporter links differing 2.5.1 and 2.6.5 template files. If Add New Item options vanish after upgrading, this is a concrete tooling lead, not necessarily a project-configuration mistake. No maintainer-confirmed fix was present. <https://github.com/microsoft/WindowsAppSDK/issues/6960>

- **MSIX tray notifications: another reproduction of duplicate launches.** An issue originally filed November 24, 2025 received a November 7 report that clicking a `Shell_NotifyIcon` balloon starts a second packaged FullTrustApplication instance even when `NIN_BALLOONUSERCLICK` is handled; the unpackaged app reportedly behaves correctly. This adds another reproduction, not a resolution: test notification activation in the packaged build, not just an unpackaged development run. <https://github.com/microsoft/WindowsAppSDK/issues/6031#issuecomment-6707639526>

## News/releases

- **Windows App SDK 2.6.6-experimental is published.** GitHub publication was November 6 at 5:43 p.m. PST. It adds hierarchical `TableView` rows through `ParentBy`, live sorting/filtering/grouping/hierarchy updates through `IsLiveShaping`, context menus and row automation; `Chart` gains UI Automation support. Other additions include zero-copy embedded-resource access and optional rendering outside scroll-view bounds. Microsoft lists fixes for XAML shutdown/restart losing dependency-property metadata, flyout theme-change crashes, inking above 100% display scaling, and style-optimization animation/tooltip regressions. These are published **experimental-channel** changes, not a new stable release or proof of production readiness. <https://github.com/microsoft/WindowsAppSDK/releases/tag/v2.6.6-exp>

- **Update: missing 2.6.5 debugging symbols are available.** The previously covered PDB issue received a November 6 contributor response stating that the symbols are now on Microsoft’s public symbol server; the issue was closed. Developers can retry symbol loading without waiting for another SDK package. Availability was not independently tested here. <https://github.com/microsoft/WindowsAppSDK/issues/6932#issuecomment-6693852376>

## microsoft-ui-xaml — past 24 hours

**Exact window:** November 6, 08:30–November 7, 08:30 PST. Issues and enabled GitHub Discussions were directly inspected, including replies on older threads.

- **Issue #12606 — GPU memory growth after moving and redrawing an Image.** Filed November 7. The reporter measured 24→305 MiB over 40 cycles when moving an Image and redrawing later; same-tick redraw and separate move-only/draw-only controls stayed flat. A new follow-up found `CanvasSwapChainPanel` stable after warm-up, but that alternative was not validated in the actual map integration. Reporter measurements, not a confirmed root cause or fix. <https://github.com/microsoft/microsoft-ui-xaml/issues/12606#issuecomment-6705087138>

- **Issue #7836 — fractional-pixel ComboBox workaround.** Originally October 15, 2022; new November 7 comment, edited that morning. The developer recommends snapping scroll offsets to whole physical pixels once scrolling settles, using `RasterizationScale` and nonanimated `ChangeView`. They say main fixes clipping but not blur; that source-fix claim was not independently verified, and shipment is not established. <https://github.com/microsoft/microsoft-ui-xaml/issues/7836#issuecomment-6707541412>

- **Issue #12603 — missing caret over acrylic on HDR.** Filed November 6 PST; November 6 evening response links an existing external-backdrop compositor limitation while explicitly leaving the HDR difference unexplained. The reporter says opaque TextBox fill, no backdrop, or SDR restores the caret. Useful mitigation leads—not a confirmed HDR-specific diagnosis. <https://github.com/microsoft/microsoft-ui-xaml/issues/12603#issuecomment-6703236331>

- **Issue #12607 — derived DispatcherTimer objects retained.** Filed November 7. The reporter’s weak-reference tests retain derived timers after stop/GC; detaching `Tick` releases owners but not those timers, whereas plain timers collect. No maintainer-confirmed diagnosis or fix; automated triage does not count as confirmation. <https://github.com/microsoft/microsoft-ui-xaml/issues/12607>

- **Issue #12434 — rendering fix now explicitly mapped to this repro.** Originally October 28; November 6 response from JesseCol confirms hybrid-GPU glyph corruption is fixed in already-shipped **2.6.5** and closes the issue, citing release notes. Newly reported issue-specific confirmation, not another release announcement. <https://github.com/microsoft/microsoft-ui-xaml/issues/12434#issuecomment-6690933895>

- **Discussion #12377 — community acrylic workaround adds ColorPicker.** Originally October 23; November 6 reply adds light/dark screenshots of ColorPicker support. This extends the community workaround’s control coverage; it is not a Microsoft framework shipment or independently verified package release. <https://github.com/microsoft/microsoft-ui-xaml/discussions/12377#discussioncomment-19446142>
