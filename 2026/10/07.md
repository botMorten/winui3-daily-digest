## Community experience

- **OpenBackupManager: a real unpackaged WinUI 3 updater, with a notification trap.** Amy Jeanes / GitHub, October 6; implementation committed at 2:04 p.m. PDT. The early-development backup project added Velopack installation and updating for its native WinUI 3 Windows tray app, including separate x64/ARM64 channels, a local update-test feed, and separate install/data folders so reinstalling cannot wipe application data. Its source also adds `EnableMsixTooling` to an unpackaged project because the author found publishing otherwise omitted compiled XAML resources; these are implementation lessons, not a claim that the project has shipped a usable backup product. <https://github.com/AmyJeanes/OpenBackupManager/commit/05daeb1f4f4a523316e74d3111f3d39674e747d2>

  The concrete pain point: an ordinary “dismiss” notification button could restart an already-quit app. In a fresh October 6 comment on a request originally opened September 10, 2022, Jeanes reports working around the builder's missing system-dismiss support with manual XML; the new code appends an action with `activationType="system"` and `arguments="dismiss"`. That is an inspectable, developer-reported workaround—not a Microsoft-confirmed or shipped SDK fix. If you build tray apps or updater notifications, test buttons on old notifications **after the app exits**, not just while it is running. <https://github.com/microsoft/WindowsAppSDK/issues/2960#issuecomment-6023652854>

- **WebView2/plugin DLL loading: stronger reproduction and a recovery boundary.** Issue #12158, opened October 4; new October 6 comment at 4:08 p.m. PDT. Contributor dotMorten's explicitly Copilot-assisted analysis reports a native unpackaged repro on ARM64 and emulated x64: `AddDllDirectory` alone failed on SDK 2.5.1 but worked with the tested 1.8 package, while full-path preload succeeded. Crucially, supplying an explicit environment after a failed Source-first initialization did not recover that control in the bounded test. Practical mitigation: preload the trusted, architecture-matching native Core DLL **before creating or setting Source on WebView2**; process-wide DLL-search changes carry plugin-compatibility tradeoffs. No upstream fix or package shipment is established. <https://github.com/microsoft/microsoft-ui-xaml/issues/12158#issuecomment-6027095701>

- **VisibilityChanged: hide/show and minimize are not interchangeable.** Issue #12160, opened October 4 Pacific time; new October 6 comment at 12:57 p.m. PDT. dotMorten's Copilot-assisted follow-up reports the missing hide/show events in a packaged 2.5.1 ARM64 app, extending the original unpackaged report. `AppWindow.Changed` with `DidVisibilityChange` covered hide/show, but not minimize/restore; `AppWindow.IsVisible` stayed true while minimized. When suspending background work, combine the relevant events and recompute visibility **and** presenter state rather than trusting one flag. This is contributor-tested guidance, not a framework fix. <https://github.com/microsoft/microsoft-ui-xaml/issues/12160#issuecomment-6024334161>

- **TreeView context menus can resurrect a stale resize cursor.** New issue #12184, October 6; follow-up at 12:53 p.m. PDT. dotMorten's Copilot-assisted controlled tests report the defect on ARM64 and emulated x64 even when Arrow was verified immediately before right-clicking. Moving the pointer after the menu opened restored Arrow in those tests; delaying before the click was insufficient. The analysis explicitly does **not** establish the reporter's broader “last non-arrow cursor anywhere” theory or a TreeView-specific root cause, and validates no reliable app-only workaround. <https://github.com/microsoft/microsoft-ui-xaml/issues/12184#issuecomment-6024265031>

- **`x:Bind` in a template's `Run`: a maintainer explains the formatting workaround.** Issue #8853, originally September 10, 2023; new October 6 reply at 7:20 p.m. PDT. Microsoft maintainer evelynwu-msft says that when a `DataTemplate` content root has no attributes and descendants use `x:Bind`, putting that root element on its own line works around the compiler bug. That explains why an earlier formatting experiment succeeded. A newly linked compiler correction, PR #12187, fixes connection-ID insertion scanning beyond opening-tag boundaries; its author reports three regression tests failing on baseline and passing with the change. The PR is **open and unmerged**, and apps would require recompilation with the corrected compiler—not just a runtime update. <https://github.com/microsoft/microsoft-ui-xaml/issues/8853#issuecomment-6029517837> <https://github.com/microsoft/microsoft-ui-xaml/pull/12187>
