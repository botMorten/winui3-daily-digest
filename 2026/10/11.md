## Community experience

- **MSIX build-task mismatch: restarting Visual Studio gets practical confirmation.** WindowsAppSDK issue, opened October 4; new comment October 11 at 08:00 PDT. <https://github.com/microsoft/WindowsAppSDK/issues/6841> — OpenNet's developer reports that restarting VS resolved `MSB4064`/`MSB4063` involving the unsupported `UseSharedPriExpansionCache` parameter. The October 5 explanation was that VS retained an older task DLL after NuGet targets upgraded; restarting was then only a suggestion. This is now a user-confirmed workaround for that setup, not a shipped SDK fix or proof that all Native AOT failures share this cause. If the error names an older task assembly than the installed targets, try restarting VS before clearing package caches. Confirmation: <https://github.com/microsoft/WindowsAppSDK/issues/6841#issuecomment-6110346371>.

## microsoft-ui-xaml — past 24 hours

**Exact window:** October 10, **08:31:08 PDT** → October 11, **08:31:08 PDT**.

- **XAML compiler speed-up merged; package availability remains unanswered.** Issue #1535, opened November 4, 2019; new merge/closure October 10 and comment October 11. <https://github.com/microsoft/microsoft-ui-xaml/issues/1535> — The issue closed at 11:09:35 PDT October 10, two seconds after PR #12062 merged. The changes cache metadata/type/member lookups and prevent repeated Pass2 rebuilds when timestamp-only XAML changes produce identical XBF bytes. The author reports a single-page Gallery edit falling from **115.745 to 30.257 seconds**, and a rebuild from **211.050 to 43.206 seconds**, using matched ARM64 source-compiler measurements. These are workload-specific author benchmarks, not independently reproduced NuGet-package results; healthy no-op builds remained roughly 14 seconds. A new commenter asked when the official release will arrive; no answer or shipped-package evidence was found by cutoff. Practical impact: promising edit/build iteration improvements, but merging source is not the same as updating your app's released toolchain. Source PR: <https://github.com/microsoft/microsoft-ui-xaml/pull/12062>; new release question: <https://github.com/microsoft/microsoft-ui-xaml/issues/1535#issuecomment-6107777162>.

- **RadioButtons resize-memory issue: experimental-package retest requested.** Issue #7640, opened August 24, 2022; new comment October 10 at 22:54:11 PDT. <https://github.com/microsoft/microsoft-ui-xaml/issues/7640> — Collaborator `Hemantxk` says a fix was put in **Windows App SDK 2.5.4-experimental** and asks the reporter to test it. This is an attributed package-fix claim, not independently verified resolution or a stable-release fix; the issue remains open without reporter confirmation. Importantly, the original custom-layout resize-leak report concerned **UWP / Microsoft.UI.Xaml 2.8.1**, not a newly introduced WinUI 3 regression. The new Windows App SDK retest request makes it relevant adjacent-framework context, but does not establish that the original UWP configuration is fixed. Comment: <https://github.com/microsoft/microsoft-ui-xaml/issues/7640#issuecomment-6106007934>.
