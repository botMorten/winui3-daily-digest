## Community experience

- **SoundWin becomes SCwin, with concrete native-app fixes.** GitHub release, **October 25**; Reddit introduction also October 25. This unofficial C#/.NET 8 WinUI 3 SoundCloud client publishes installer/portable builds and openly describes its AI-assisted development. The latest edge release addresses repeated network reloads when switching tabs, profile-page UI-thread marshaling and assigning the ViewModel before `InitializeComponent`; it also adds playback-state restoration and tray behavior. Useful real-world adoption evidence, but these are the developer’s release claims—not independent performance verification or a stable-channel endorsement. Original introduction: <https://www.reddit.com/user/yunoteru4ever/comments/1xf3y1c/soundwin_a_native_winui_3_c_soundcloud_desktop/> · Release: <https://github.com/djell1l/SoundWin/releases/tag/v0.1.0-edge.9>

- **TypeWhisper’s WPF removal accidentally dropped mouse hotkeys.** **Catch-up: October 24 merge / October 25 daily release.** The WinUI dictation app restores middle/back/forward-button global shortcuts, preserving imported shortcut tokens. Its implementation uses a shared low-level mouse hook on a dedicated message-loop thread, consumes matching press/release pairs, and orders mouse events before queued keyboard events—a useful migration lesson beyond swapping controls. The fix appears in the **1.3 Daily prerelease**, not established here as a 1.2 stable fix; the PR’s manual Windows validation checklist remains incomplete. <https://github.com/TypeWhisper/typewhisper-win/pull/719> · <https://github.com/TypeWhisper/typewhisper-win/releases/tag/v1.3.0-daily.20261025.136>

- **A local-AI port reaches a recognizable WinUI prototype—not a shipping application.** David Gewirtz, ZDNET, **October 26**. In a hands-on experiment, OpenCode/Qwen translated his Swift Mac icon app into C#, first using WPF to establish functionality and then migrating to WinUI 3; he reports recognizable rendering after roughly four hours. Crucially, he explicitly says substantial distribution work remains and he does not plan to ship the Windows port: an interesting workflow example, not proof of production-ready autonomous migration. <https://www.zdnet.com/innovation/lenovo-yoga-9n-rtx-spark-review/>

## microsoft-ui-xaml — past 24 hours

**Exact window:** October 25, 2026, **08:30 PDT** → October 26, 2026, **08:30 PDT**. Issues and Discussions inspected directly, including older issue threads with new activity.

- **Discussion: first-party TableView setup guidance.** New **October 26**, Team WinUI’s walkthrough covers sorting, filtering, grouping, editing, virtualization and frozen columns in `Microsoft.UI.Xaml.Controls.Tabular`. It specifies `XamlControlsResources` plus `TabularControlsResources` and recommends **self-contained deployment** to avoid the known framework-dependent startup problem. This is guidance for **Windows App SDK 2.5.4-experimental**, not a package released today; hierarchical views/context menus remain unfinished. No comments or replies at collection. <https://github.com/microsoft/microsoft-ui-xaml/discussions/12400>

- **Issues: compact NavigationView footer icons—source fix merged.** Two older reports, opened **March 2025 / May 2026**, closed **October 26** when PR #12319 merged. It repairs compact-pane layout for `NavigationViewItem` hosted directly in `PaneFooter`/`PaneCustomContent`; normal `FooterMenuItems`/`MenuItems` were not affected. Treat this as a verified merged fix, **not yet a verified shipped fix**. <https://github.com/microsoft/microsoft-ui-xaml/issues/10415> · <https://github.com/microsoft/microsoft-ui-xaml/issues/11108> · <https://github.com/microsoft/microsoft-ui-xaml/pull/12319>

- **Issue: shutdown crash with off-thread Page destruction.** New **October 26** report on SDK **2.5.1** supplies finalizer/UI-thread stacks and attributes the crash to a null `DXamlCore::GetCurrent()` during `Page` destruction. A suggested null guard is reporter analysis, not a maintainer-confirmed remedy; the only reply was automated triage. <https://github.com/microsoft/microsoft-ui-xaml/issues/12404>

- **Issue: a fresh explanation for repeated XAML compilation.** Opened **October 19**, with a new human comment **October 26**: unchanged output timestamps can leave outputs older than touched inputs and repeatedly trigger `MarkupCompilePass2`. The contributor compares a similar package-fragment timestamp problem; its related PR remains open and does not establish that this XAML issue is fixed. <https://github.com/microsoft/microsoft-ui-xaml/issues/12334#issuecomment-6417268477>
