## Community experience

- **Wintodo update: the engineering behind a native Store app—and its current limits.** Reddit r/dotnet, **November 21, 17:36 PST**. Following the app’s November 20 coverage, this new developer-focused post explains keeping WinUI 3 + .NET 10 Native AOT compatible by using raw SQLite/FTS5 and hand-written mappers instead of EF Core/reflection-based JSON; compiled `x:Bind` templates plus a custom `IObservableVector`/SequenceDiff avoid rebuilding ListView contents during sorting/filtering. In fresh replies, the author says multiple accounts are **not supported yet**; mobile users can use compatible CalDAV clients now, while a dedicated Kotlin Multiplatform companion is only planned. Useful implementation lessons and product constraints, not another announcement of the same release. Published performance numbers remain author measurements, not independently reproduced benchmarks. <https://www.reddit.com/r/dotnet/comments/1y2d61m/i_built_a_native_winui_3_net_10_native_aot/> · <https://github.com/Dvaderfun/wintodo>

- **AI capability detection reportedly throws instead of returning an unsupported result.** WindowsAppSDK GitHub issue, **November 21, 14:19 PST**. A developer reports `AICapabilities.HasAICapability(CopilotPlusPC)` failing with `FileNotFoundException`/`0x8007007E` in SDK 2.6.5, MSIX-packaged, framework-dependent apps on some Windows 10/11 devices. For apps conditionally exposing AI features, this is a warning that the capability-check path itself may fail; no missing module, cause, workaround or verified fix has been established, and there are no human replies yet. <https://github.com/microsoft/WindowsAppSDK/issues/6997>

## News/releases

- **Catch-up — zero-copy PRI resource access proposed for the stable branch.** WindowsAppSDK PR, opened **November 20, 16:09 PST**, missed before yesterday’s cutoff. The proposal brings `ResourceCandidate.ValueAsMemoryBuffer` to `release/2.0-stable`, allowing embedded resource bytes to be read from mapped PRI data without repeated copying, while retaining the resource manager for safe lifetimes and preserving `ValueAsBytes` compatibility. The author reports private-build WinUI testing and intended WinUI adoption, but the PR remains **open/unmerged**: no public package or measured application-level performance gain is established. <https://github.com/microsoft/WindowsAppSDK/pull/6996>
