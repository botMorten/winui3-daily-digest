## Community experience

- **MSIX bundle signing: SHA384 setting apparently ignored — catch-up.** WindowsAppSDK issue, opened October 13 Pacific (October 14 UTC): <https://github.com/microsoft/WindowsAppSDK/issues/6865>. A developer needing to sign an MSIX bundle with a SHA384 certificate reports that setting `AppxDefaultHashAlgorithmId` to `SHA384` still produces a SHA256 block map, with a blank-app reproduction and generated XML attached. There are no replies or verified workaround in the inspected record. This is a packaging/signing report, not a WinUI rendering bug; inspect the generated bundle rather than assuming the project property took effect. The latest update timestamp alone does not establish a fresh diagnosis.

- **An old restore workaround gets fresh confirmation.** WindowsAppSDK issue originally September 2024; new reply October 14: <https://github.com/microsoft/WindowsAppSDK/issues/4698#issuecomment-6172736283>. A developer confirms that an earlier suggestion to run `dotnet restore` worked for the `Microsoft.Windows.SDK.NET.Ref`/NETSDK1112 build-error discussion, while criticizing the error message. Useful as a low-cost diagnostic step when package restore is incomplete—not evidence that every SDK-upgrade failure has the same cause, or that a new SDK fix shipped.

## microsoft-ui-xaml — past 24 hours

**Exact window:** October 14, 2026, 08:30 PDT → October 15, 2026, 08:30 PDT. Direct inspection covered 16 issues and all 643 accessible Discussions, including older threads’ comments/replies; pagination completed.

- **ContentDialog animation: merged source fix, not verified in a package.** July 20 issue; new closure/source merge October 14: <https://github.com/microsoft/microsoft-ui-xaml/issues/11257>. With `OptimizeApplyStyles`, delayed style application left the dialog template unresolved until re-parenting canceled its entrance animation. [PR #11736](<https://github.com/microsoft/microsoft-ui-xaml/pull/11736>) applies the built-in style before expanding the template and reports retaining the optimization. It merged into `main`; no fixing NuGet release was verified.

- **New ItemContainerGenerator lifetime-crash reproduction.** Opened October 14 Pacific/October 15 UTC: <https://github.com/microsoft/microsoft-ui-xaml/issues/12289>. The reporter retains a generator while switching a ListView from `VirtualizingStackPanel` to `ItemsStackPanel`; `RemoveAll()` reportedly clears its item map before failing on the detached host, allowing a subsequent `GeneratorPositionFromIndex()` call to crash. Includes a C++/WinRT repro against 2.5.1. Relevant if custom controls cache generators; this is a reporter diagnosis, not maintainer confirmation. Automated triage adds no independent validation.

- **New Discussion: C++/WinRT XAML named modules.** October 15: <https://github.com/microsoft/microsoft-ui-xaml/discussions/12305>. A contributor proposes opt-in `.xaml.g.ixx` declarations, an `Application_Xaml` aggregator and MSBuild dependency/cleanup integration, addressing forced-include workarounds and stale incremental artifacts. The author reports fork CI and x64 native-consumer validation, not measured build-speed gains. Despite PR-style wording, this is a **Discussion/proposal**, not an accepted upstream feature or released package.

- **ToggleSwitch focus stealing: new proposed fix for an old issue.** February 2024 issue; fresh linked PR October 15: <https://github.com/microsoft/microsoft-ui-xaml/issues/9331>. [PR #12290](<https://github.com/microsoft/microsoft-ui-xaml/pull/12290>) attributes focus jumping to `RootScrollViewer` to stale pressed state when a child handles pointer release, and proposes cleanup through the handled-events-too path. Some diagnostic cases passed according to the author, but two-contact and touch/pen/capture validation remain pending. **Open PR, not merged or shipped.**

- **PagerControl styling moves to an upstream proposal.** October 13 issue; fresh PR October 14: <https://github.com/microsoft/microsoft-ui-xaml/issues/12266>. [PR #12287](<https://github.com/microsoft/microsoft-ui-xaml/pull/12287>) replaces ButtonPanel’s bordered appearance with rounded Fluent styling—new source work beyond the previously reported community workaround. It remains open; no package fix was verified.

- **New compact NavigationView selection report.** October 15: <https://github.com/microsoft/microsoft-ui-xaml/issues/12303>. Programmatically selecting a hierarchical child reportedly updates `SelectedItem` and the child’s `IsSelected`, but leaves the parent’s `IsChildSelected` false when the left pane is closed. The reporter supplies a minimal setup and says removing navigation handlers or delaying selection did not help. Test compact and expanded navigation separately; no human-confirmed fix is present, and an AI-suggested duplicate is not an accepted duplicate relationship.
