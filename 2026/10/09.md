## Community experience

- **WebView2 initialization timing can derail accessibility scans.** WindowsAppSDK #6850, opened **October 9**: <https://github.com/microsoft/WindowsAppSDK/issues/6850>. A developer supplies four WinUI 3 scenarios: setting `Source` in XAML or calling `EnsureCoreWebView2Async()` before `Loaded` reportedly produces a repeating UI Automation hierarchy, still repeating at a 30,000-node cap. Tested 1.6 and 2.5.1 configurations reproduce it; tested 1.5 configurations do not. Deferring either operation until `Loaded` avoids the problem in their control cases. This is a **reporter-tested workaround**, not a maintainer-confirmed diagnosis or framework fix—worth checking when Accessibility Insights or automated inspection becomes unexpectedly slow after upgrading.

- **Self-contained packaging gets a testable subfolder feature—and an AOT complication.** #6353, originally **March 27**, new replies **October 8–9**: <https://github.com/microsoft/WindowsAppSDK/issues/6353#issuecomment-6070004237>. Following the previously covered prototype, contributor guimafelipe points to MSIX BuildTools **1.7.261008100** and says `PackageSubfolder` was renamed `MsixSubfolder`. The reporter then describes Debug success but a Release duplicate-payload error with an AOT WinRT COM server, supplies a repro, and says non-AOT builds work. Useful progress for apps combining background components and COM servers, but **not a blanket resolution** of self-contained packaging conflicts.

## News/releases

- **New MSIX BuildTools targets multi-architecture certificate conflicts.** NuGet lists **1.7.261008100**, dated **October 8**: <https://www.nuget.org/packages/Microsoft.Windows.SDK.BuildTools.MSIX/1.7.261008100>. In #6765—originally **September 17**, updated **October 8**—guimafelipe says it fixes x64/ARM64 bundle installation failures caused by multiple certificates beside `Install.ps1`: <https://github.com/microsoft/WindowsAppSDK/issues/6765#issuecomment-6069974412>. The package is available and the thread closed; there is no fresh independent installation confirmation. The contributor calls the subfolder change a preview for testing despite the numeric version. This is a **packaging-tool update**, not a new WinUI runtime release.

## microsoft-ui-xaml — past 24 hours

**Exact window:** October 8, 2026, 08:30 PDT → October 9, 2026, 08:30 PDT. Older threads below have newly verified activity.

- **Extended-title-bar retention: stronger reproduction.** Yesterday’s WindowsAppSDK #6848 transferred to **issue #12210** on October 8: <https://github.com/microsoft/microsoft-ui-xaml/issues/12210#issuecomment-6064444932>. dotMorten posted Copilot-labelled controlled results on packaged, self-contained **2.5.1**: roughly 37–39 handles retained per closed extended-title-bar window versus about two for ordinary windows. Disabling extension alone did not help; `ResetToDefault()` sharply reduced retention. These are attributed contributor results and a bounded mitigation, **not an independently verified root cause or shipped fix**.

- **DataTemplate/TextBlock.Run `x:Bind` fix merged.** Older **issue #8853** closed **October 8**, following verified merge of PR #12187: <https://github.com/microsoft/microsoft-ui-xaml/issues/8853>. The connection-ID rewriter now stops at opening-tag delimiters, with regression tests for formatting variants. Applications need recompilation using a compiler containing the change; **released-package availability was not established**.

- **C++/WinRT Char/Guid and array projection fixes landed.** Older **issue #11069** closed **October 8** after PR #12167 merged: <https://github.com/microsoft/microsoft-ui-xaml/issues/11069>. Generated metadata now projects one-dimensional arrays as `winrt::com_array<T>` and maps Guid/Char to `winrt::guid`/`char16_t`. This also addresses related array issue #7726. **Source merged, not package shipment**; broader array-boxing and multidimensional support are not promised.

- **New ContentIcon proposal challenges fragile icon hacks.** **Issue #12215**, opened **October 8**: <https://github.com/microsoft/microsoft-ui-xaml/issues/12215>. It proposes arbitrary `UIElement` content in standard icon slots, instead of injecting visuals into private internal Grids that optimizations can remove. Related PR #12214 remains open and adds PathIcon Grid-preservation tests—not ContentIcon itself. **No supported API or release commitment yet.**

- **TransformToVisual mitigation does not fit every app.** In older **issue #12156**, the reporter said **October 9** that calls originate inside a third-party grid, preventing application of the suggested workaround: <https://github.com/microsoft/microsoft-ui-xaml/issues/12156#issuecomment-6079371227>. This is a newly documented practical limitation, not new independent measurements or a fix.

- **Shared-runtime failures gain a different-stage report.** A new participant in older **issue #12169** reported **October 9** that Runtime **2.5.1 x64** affects several inbox apps and WhatsApp: <https://github.com/microsoft/microsoft-ui-xaml/issues/12169#issuecomment-6082507814>. Their DLL-loading/CoreMessagingXP Bad Image failure differs from the original parser crash. **Same root cause and a validated repair remain unconfirmed.**
