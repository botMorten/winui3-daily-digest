## Community experience

- **Extended title bars add measurable work in a minimal repro** — WindowsAppSDK issue, **Nov 22**. With SDK 2.7.0, .NET 10 and an unpackaged Release x64 app, the reporter’s synchronous cross-process `SetWindowPos` summary rose from **1.86 to 6.91 ms** merely enabling `ExtendsContentIntoTitleBar`, without custom caption colors or a backdrop. ETW traces identify title-bar recalculation, region updates and painting: useful places to investigate similar symptoms, but these are one reporter’s measurements, not interactive drag benchmarks, an older/newer SDK comparison, or a confirmed fix. <https://github.com/microsoft/WindowsAppSDK/issues/6998>

- **Notification activation proposal revived—with a narrow scope** — WindowsAppSDK PR, originally **Oct 23**, new author explanation **Nov 22 PST**. The author explains guards that check the wait handle created by `Register()` before notification deserialization waits, avoiding a null-handle fail-fast when registration never happened. The inspected source proposal remains unmerged, with no new functional test; it does **not** address the separate unpackaged Push missing-payload exception. <https://github.com/microsoft/WindowsAppSDK/pull/6892#issuecomment-7090169682>

No additional independent blog/Reddit/app-release story cleared freshness and dedup checks today; Wintodo, Machitan, Reactor and RHI results mostly repeated earlier coverage.

## News/releases

- **Unpackaged application-data context gets sharper review guidance** — WindowsAppSDK API-spec PR, originally **Nov 5**, new review **Nov 22**. Microsoft contributor Howard Kapustein agrees to a proposed `GetContextForUnpackaged()` and same-value setter idempotency, while changing an established context remains disallowed—relevant to libraries sharing an unpackaged host’s data location. This is **review intent**, not an implemented or shipped API: the inspected spec still contains the older repeated-setter error semantics. <https://github.com/microsoft/WindowsAppSDK/pull/6946#discussion_r4660081635>

## microsoft-ui-xaml — past 24 hours

Exact rolling window: **November 22, 08:30 PST → November 23, 08:30 PST**. Older threads below have verified new activity, not merely recent `updated_at` values.

- **NavigationView returns space after children collapse — Issue**. Originally **Mar 16, 2023**; **Nov 22, 21:18 PST**, PR #12560 merged and the issue closed. The source fix addresses vertical StackPanel/ScrollViewer and non-stretched finite-height hosts while preserving normal stretched-host and Top-mode behavior. Relevant to expanding navigation trees; **source merge verified, shipped package not established**. <https://github.com/microsoft/microsoft-ui-xaml/issues/8291> <https://github.com/microsoft/microsoft-ui-xaml/pull/12560>

- **Removing one native snap-point handler silences the others — Issue**. New **Nov 23, 05:37 PST**: Martin Zikmund reports a raw-ABI reproduction on SDK 2.5.1 in which StackPanel stops notifying remaining subscribers after one unsubscribes. Ordinary C# multicast subscriptions alone avoid that registration pattern; ScrollViewer impact is a code-reading inference, not an end-to-end repro. PR #12813 proposes four condition corrections and a regression test, but remains open; the fixed build/tests were not run by the author. <https://github.com/microsoft/microsoft-ui-xaml/issues/12812>

- **ImageBrush rotation/downscaling still under-decodes — Issue**. New **Nov 22, 20:33 PST**: a contributor identifies incorrect axis sizing with rotated brush transforms and premature natural-size clamping before rasterization scaling. One example decodes **200×200** where drawing needs **400×400**, explaining persistent blur. These cases are explicitly outside the still-open scale-improvement PR #12777; no fixing follow-up merge was found. <https://github.com/microsoft/microsoft-ui-xaml/issues/12807>

- **TableView selection limitation acknowledged; column chooser requested — Discussion**. Original **Nov 19** tutorial; **Nov 22–23 PST**, two new contributions: Microsoft member pranav-gupta-msft acknowledges selection is currently index-based and will examine alternatives, while another developer asks for individual column visibility toggles rather than “show all, then hide again.” The latter concerns the sample’s app-defined menu, not a demonstrated control impossibility. Neither response constitutes an API commitment or new release. <https://github.com/microsoft/microsoft-ui-xaml/discussions/12762>

- **Keyboard re-entry behavior clarified — Issue**. Original **Oct 28**; **Nov 22, 20:25 PST**, a contributor closes the TableView focus-restoration report: Tab/Shift+Tab enters through the header, then Down restores the last-focused row/cell. The referenced source fix merged **Nov 6**, not today; useful keyboard/accessibility guidance, with no tested shipping version named. <https://github.com/microsoft/microsoft-ui-xaml/issues/12447#issuecomment-7091574913>

- **Selection pill dropped by design — Issue**. Original **Oct 21**; **Nov 22, 09:16 PST**, a contributor closes the horizontal-scroll indicator bug after design review: selection should use a rectangular row outline instead of the blue pill. This is a new design decision, not evidence of a shipped rendering repair. <https://github.com/microsoft/microsoft-ui-xaml/issues/12358#issuecomment-7082713509>
