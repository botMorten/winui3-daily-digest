## Community experience

- **MSIX Advertising ID may ignore subsequent privacy-setting changes.** WindowsAppSDK issue, October 19 PDT. A C++/WinRT developer reports that the first `AdvertisingId()` read becomes stuck in the app’s virtualized registry hive: turning advertising off still returns the old ID, while resetting the app merely caches the next state. The author reports disabling registry-write virtualization resolves it, but that changes isolation/capability requirements and is not a maintainer-endorsed fix. If your packaged app uses this API, test the full on/off/relaunch sequence rather than assuming each read reflects current consent. <https://github.com/microsoft/WindowsAppSDK/issues/6879>

- **Mixed-codec HLS exposes a native-media integration problem.** WindowsAppSDK issue, October 20. A developer building an unpackaged WinUI 3 player reports `MF_E_UNSUPPORTED_FORMAT` when Windows selects H.264 followed by HEVC from one HLS master. Smaller tests also fail outside WinUI, so this is not established as a XAML regression; the report is from one installation, and its public comparison stream is not a deterministic repro. Neither source-buffer abort nor reopening fixed the author’s case; a supported codec-switching pattern remains unanswered. <https://github.com/microsoft/WindowsAppSDK/issues/6880>

- **Catch-up — Vaimail shows native appeal, and the gaps users immediately notice.** r/windowsapps, October 16; visible comments October 16–18. The designer behind this free, closed-source WinUI 3 mail/calendar app describes Store distribution, tray persistence and multiple accounts. Visible readers praise its appearance but request folder management and flexible reading-pane placement; one reports emails taking 5–6 seconds to appear. The author also discloses Gmail app-password requirements. It’s a useful adoption example—not independent evidence of security, reliability or Outlook feature parity. <https://www.reddit.com/r/windowsapps/comments/1x7qjax/i_got_tired_of_webview_apps_on_windows_so_i_built/>

- **Catch-up — QuickRun keeps the classic Run workflow while using WinUI 3.** Giosuè Giordano, DEV, October 16; repository release October 15. The WinUI 3/.NET 8 project combines app discovery, Store-app launching, command arguments and a calculator—for example, `notepad test.txt` and `2+2`. Command history, smarter ranking and global hotkeys remain roadmap items in the author’s post, so treat this as an actively developed launcher rather than a complete Win+R replacement. <https://dev.to/giosuoffice/modernizing-winr-with-winui-3-2kd3> · <https://github.com/GiosuOffice/QuickRun>

## News/releases

- **Catch-up — DevWinUI 10.8.0 targets navigation and time-setting correctness.** Maintainer release, October 15. The community library adds `DateTimeHelper`, deferred JSON navigation configuration and multi-JSON mapper support, alongside navigation/loading fixes. Its time-format fix follows changes to Windows’ 12/24-hour preference rather than relying on cached culture information—a concrete issue to check in clock and date/time interfaces. This is a DevWinUI library release, not a Windows App SDK release. <https://github.com/ghost1372/DevWinUI/releases/tag/v10.8.0>

- **Catch-up — Photos’ rebuilt Editor is explicitly WinUI 3.** Microsoft Windows Experience Blog, October 15. Microsoft says the native Editor launches 25% faster versus Photos 2026.11060 in its controlled tests, with HDR, HEIC and WebP editing; rollout starts with Insiders, with broader availability planned later this year. The announcement also calls the Viewer native, but does not establish that the entire Gallery is WinUI 3. Relevant adoption evidence, with app-specific performance claims—not a general framework benchmark. <https://blogs.windows.com/windowsexperience/2026/10/15/meet-the-new-photos-app-on-windows-11/>

## microsoft-ui-xaml — past 24 hours

**Exact window:** October 19, 2026, 08:30 PDT → October 20, 2026, 08:30 PDT. Direct API inspection covered 56 issue candidates, excluding pull requests, and all 644 available Discussions with their comment/reply trees; routine bot triage was not treated as developer discussion.

- **Discussion — Chart gets an official finance-dashboard walkthrough (new October 20).** A Microsoft member supplies a minimal runnable sample for the existing **2.5.4-experimental** control: merge chart and control resource dictionaries, use self-contained deployment to avoid the reported resource-lookup problem, and assign replacement `Samples` when refreshing data rather than assuming in-place edits redraw. Point-label overrides use indexes, so reordering data requires updating them. Useful prototype guidance; APIs remain experimental. <https://github.com/microsoft/microsoft-ui-xaml/discussions/12343>

- **Issues — two distinct incremental-XAML build problems.** New October 19 report #12334 says touching unchanged XAML leaves compiled outputs older than sources, forcing repeated Pass2 work—11–14 seconds per build in the author’s 69-page app. Its workaround deletes stale page outputs before Pass2, with path-mapping caveats. Separately, a new October 19 comment on #11264 (opened July 21) says a prior source fix still is absent from tested 2.5.1/2.5.4-experimental compiler binaries; its comma-valued optional-change-properties workaround still helps that different bug. These are reporter-tested observations, not independently reproduced or confirmed shipped fixes. <https://github.com/microsoft/microsoft-ui-xaml/issues/12334> · <https://github.com/microsoft/microsoft-ui-xaml/issues/11264#issuecomment-6271058221>

- **Issue — window sizing can break placement before activation (new October 20).** #12345 reports that setting `Window.Height/Width` prevents pre-activation `AppWindow.Move`. Sizing through `AppWindow.Resize` reportedly avoids it, potentially preventing visible repositioning after activation. A repro is supplied; no human confirmation or framework fix yet. <https://github.com/microsoft/microsoft-ui-xaml/issues/12345>

- **Issue — proposed TeachingTip binding-preservation fix (new activity October 19).** #8095 (opened January 13, 2023) gained PR #12336, intended to stop an already-closed tip from overwriting a bound `IsOpen` value when its target unloads. The author reports 70/70 API tests plus interaction checks. The PR is **open and unmerged**, not a shipped fix. <https://github.com/microsoft/microsoft-ui-xaml/issues/8095> · <https://github.com/microsoft/microsoft-ui-xaml/pull/12336>
