## Community experience

- **A customer-crash investigation changes direction.** WindowsAppSDK #6724, originally August 27; substantive update October 21. The developer captured originating stowed-exception stacks and now traces the dominant failure to synchronous `UIElement.Measure` during an MFC host swap, triggering layout/`x:Bind` on a temporarily disconnected tree. Per-user saved UI layouts explain why one account crashes and another works. Their app-side reentrancy guard and transient-error fallback are rolling out, but telemetry has not validated the fix; the specific “package not found” variant remains unresolved. Practical lesson: a fail-fast inside `Microsoft.UI.Xaml.dll` does not by itself establish a framework-registration defect. <https://github.com/microsoft/WindowsAppSDK/issues/6724#issuecomment-6313417378>

- **Removing notification registration’s icon does not necessarily refresh the visible attribution icon.** WindowsAppSDK #6882, October 20. An unpackaged SDK-only WinForms diagnostic removes `IconUri` via parameterless `Register()`, yet the next delivered toast still shows the old custom icon. This matters to WinUI apps using the same notification service, but reproduction is limited to SDK 2.0.1 and a preview Windows build—not current SDK/retail Windows. The author explicitly says this is not a release blocker and has not tested replacing one valid custom icon with another; no upgrade regression or supported workaround is established. <https://github.com/microsoft/WindowsAppSDK/issues/6882>

- **Catch-up — unpackaged `ResourceManager()` failure has a detailed, unconfirmed native diagnosis.** WindowsAppSDK #6883, October 18. The author’s agent-assisted disassembly report alleges that `MRM.dll` omits a path separator from buffer sizing when locating `resources.pri`, producing `0x8007007A` in tested 2.x binaries and potentially heap corruption in 1.6. There is a standalone path-combination repro, but that is not independent verification of every claimed SDK failure. Useful when diagnosing unpackaged resource loading; automated triage is not maintainer confirmation, and no shipped fix was verified. <https://github.com/microsoft/WindowsAppSDK/issues/6883>

- **Catch-up — TrenchHQ separates desktop placement from widget content.** Gautam Gupta, DEV, October 17. This MIT-licensed, Store-distributed Windows x64 app uses WinUI 3/.NET plus Rust and Node components for floating overlays and screen-edge panels. The reusable design lesson is that panels own position, monitor and window behavior while widgets own data, allowing saved content to move across layouts. The author’s post is newly discovered coverage, not a new binary release: the checked v1.0.2 release dates to September 29. <https://dev.to/gautamgpt1/i-built-an-open-source-windows-desktop-companion-for-crypto-with-winui-3-rust-and-node-6gp> · <https://github.com/gautamgpt1/TrenchHQ>

## microsoft-ui-xaml — past 24 hours

**Exact window:** October 20, 2026, 08:30 PDT → October 21, 2026, 08:30 PDT. Direct API inspection covered 131 updated issues, excluding PRs, and all 644 available Discussions with comment/reply trees. Ten issues were newly created; most comment traffic was automated triage, not developer conversation.

- **Issue — display-off bitmap updates accumulate memory (new October 20).** #12355 supplies a WinUI-only repro reporting roughly 150–170 MB retained until the display returns. The author reports that pausing `WriteableBitmap` updates when the display is off avoids accumulation. Their much larger overnight out-of-memory problem is not proven to have the same cause; this is an author-tested mitigation, not a confirmed framework fix. <https://github.com/microsoft/microsoft-ui-xaml/issues/12355>

- **Issues — fresh title-bar diagnostics offer two workarounds (October 21 activity).** The October 12 hide/restore report #12232 gains a user-tested `WM_NCMOUSEMOVE`/`HTNOWHERE` hover-reset workaround. New #12359 separately traces inactive title-bar appearance to activation/foreground ordering and proposes showing without activation, acquiring foreground, then calling `Window.Activate()`. Neither diagnosis is maintainer-confirmed. <https://github.com/microsoft/microsoft-ui-xaml/issues/12232#issuecomment-6311287202> · <https://github.com/microsoft/microsoft-ui-xaml/issues/12359>

- **Discussion + issue — experimental Chart gets concrete feedback (October 20–21).** Yesterday’s walkthrough Discussion #12343 now has requests for zoom/pan, pie charts and API/design clarification, plus criticism of contrast and overlapping labels. New #12350 reports that the Gallery forecast series overlaps axes; disabling that series reportedly avoids it. These are experimental-control feedback and a reporter workaround, not another release or an official feature commitment. <https://github.com/microsoft/microsoft-ui-xaml/discussions/12343> · <https://github.com/microsoft/microsoft-ui-xaml/issues/12350>

- **Issue — test-template work advances to a draft implementation (October 20).** A new #11267 comment and linked WindowsAppSDK PR #6885 add concrete work on MSTest/Microsoft.Testing.Platform and packaged/unpackaged template choices. The PR remains **open and draft**, with packaged MTP still failing in VS Test Explorer despite command-line support. Do not read this as shipped template support. <https://github.com/microsoft/microsoft-ui-xaml/issues/11267#issuecomment-6295189221> · <https://github.com/microsoft/WindowsAppSDK/pull/6885>

- **Issues — TableView feedback identifies missing visual information (new October 20–21).** #12352 reports blank group headers in the experimental Gallery sample; #12358 supplies steps showing the selected-row indicator disappearing during horizontal scrolling. Both are open reports without a verified fix—useful checks before adopting the experimental control for dense data interfaces. <https://github.com/microsoft/microsoft-ui-xaml/issues/12352> · <https://github.com/microsoft/microsoft-ui-xaml/issues/12358>
