## Community experience

- **Registry Editor as a concrete C#-first WinUI example** — Windows Latest, **November 8**. <https://www.windowslatest.com/2026/11/08/microsoft-built-a-native-winui-registry-editor-that-makes-windows-11s-regedit-look-like-windows-95-and-i-tried-it/>
  The author compiled Microsoft.UI.Reactor’s Registry Editor sample into a self-contained portable folder and reports responsive navigation, with a brief loading placeholder when expanding large registry branches. The original source confirms real `Microsoft.Win32` registry reads/writes, background enumeration and synchronization-context posting back to the UI: useful implementation material for developers exploring MVU without XAML, rather than a WebView wrapper. This is new hands-on coverage of older code, not a fresh Reactor release; favorites are session-only, import/export uses the clipboard, and permissions/hive-loading remain unfinished—study or test it in a VM, not as a production regedit replacement. Source: <https://github.com/microsoft/microsoft-ui-reactor/tree/main/samples/apps/regedit>.

## microsoft-ui-xaml — past 24 hours

**Exact window: November 7, 2026, 08:30 PST–November 8, 2026, 08:30 PST.** Both Issues and enabled GitHub Discussions were inspected directly, including comments/replies on older threads.

- **Issue: closing a tab can crash when its content still owns focus** — opened **November 7, 18:48 PST**; native-stack comment at **18:52 PST**. <https://github.com/microsoft/microsoft-ui-xaml/issues/12611>
  EricBerridge reports an access violation in `FocusProperties::IsScrollable` when removing a selected TabView tab containing SelectorBar, ItemsView or ScrollView. Their ScrollViewer/Button controls and equivalent content outside TabView survive, narrowing the reproduction on unpackaged, self-contained x64 WinUI/Foundation 2.6.5. Moving focus outside TabView before removal, then refocusing a remaining element, reportedly survived 35 minutes of the same stress test. Practical implication: exercise close-tab behavior with keyboard focus inside these controls; the diagnosis and mitigation remain reporter-only, with no human maintainer confirmation or shipped fix. Stack: <https://github.com/microsoft/microsoft-ui-xaml/issues/12611#issuecomment-6716387460>.

- **Issue: deterministic metadata generation now has a merged source fix** — original issue **October 27**; new merge/closure **November 7, 13:46 PST**. <https://github.com/microsoft/microsoft-ui-xaml/issues/12412>
  PR 12596 sorts reflected types and properties using ordinal ordering and updates the generated metadata header; codendone then closed the issue. This reduces ordering churn and spurious generated-file diffs for source contributors. It is verified work merged into `main`, not evidence of a newly shipped NuGet fix or runtime performance improvement. Fix: <https://github.com/microsoft/microsoft-ui-xaml/pull/12596>.

- **Discussion: “Can we get the Store’s expandable hover card?”** — opened **November 7, 17:56 PST**; community response **21:33 PST**. <https://github.com/microsoft/microsoft-ui-xaml/discussions/12610>
  Lyorcloud asks for the exact Store control identified as `PopupCardButton`. ghost1372 points to DevWinUI and says they have ported some Store controls, including carousel. That is a useful community-library lead, not confirmation that this particular hover card is public or implemented there. The thread had one new comment and two participants including the opener. Response: <https://github.com/microsoft/microsoft-ui-xaml/discussions/12610#discussioncomment-19468808>.
