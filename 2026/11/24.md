## News/releases

- **Malicious packages masquerade as WinUI controls and assessment tooling.** Socket threat research, November 23. Researchers identify 13 NuGet packages tied to fake developer assessments; their analysis shows build-time execution through MSBuild targets, plus controls that trigger downloaded payloads at runtime. NuGet's official removal log independently labels `Web3TotalButton`, `VS_Builder.MSBuildAnalyzer` and `VS_Builder.WinUI3Controls` as malware. Practical takeaway: inspect extra package feeds, committed `.nupkg` files and imported build targets **before building**; use a disposable credential-free VM for unfamiliar assessments. Socket said `WinUI.Button` remained listed at publication; that listing was not rechecked today. This is a supply-chain attack, **not a vulnerability attributed to WinUI itself**. <https://socket.dev/blog/malicious-nuget-packages-fake-job-assessments> · <https://github.com/NuGet/NuGetGallery/blob/main/RemovedPackages.md>

- **A real WinUI 3 app behind local AI integration.** Microsoft .NET blog, November 23. The walkthrough uses **Llama on Windows**, a .NET 10/WinUI 3 tray app, as a local OpenAI-compatible server for a .NET 11 C# sample using `IChatClient`, streaming and automatic function invocation. It is a concrete native-app adoption example and integration pattern, not a new Windows App SDK AI API; tool support depends on the model. Original article, app source and sample were inspected, but nothing was installed or benchmarked. <https://devblogs.microsoft.com/dotnet/local-models-dotnet-llama-windows/> · <https://github.com/ggml-org/Llama-Windows>

## microsoft-ui-xaml — past 24 hours

**Exact window: November 23, 08:32 → November 24, 08:32 PST.** Older issues below have newly verified source proposals or review activity within this window.

- **Issue #11028 — console-subsystem UIA crash gets an entry-point diagnosis.** November 24's PR #12823 attributes the older crash to `OutputType=Exe` causing generated code to omit `STAThread`. The collaborator reports the sample crashed 6/6 under deep UI Automation walks on SDK 1.8/2.7.0, while `EnableWin32Codegen=true` survived 3/3 and retained console output. That is an author-tested workaround and open compiler proposal—not a shipped fix or an explanation for every UIA crash. <https://github.com/microsoft/microsoft-ui-xaml/issues/11028> · <https://github.com/microsoft/microsoft-ui-xaml/pull/12823>

- **Issue #11047 — navigation fast-fail narrowed to transitioning TabView content.** New PR #12820 traces a failure to a ContentPresenter re-adding its still-unloading Page; animations may explain inconsistent reproduction. The author reports red/green testing, but a fresh review flags reentrant callbacks potentially changing the template during cancellation. The proposal remains open and owner-review-pending; no fixed runtime is available from this evidence. <https://github.com/microsoft/microsoft-ui-xaml/issues/11047> · <https://github.com/microsoft/microsoft-ui-xaml/pull/12820>

- **Issue #12821 — TreeView's `RemoveAtEnd` removes the wrong node.** New November 24 source-level repro: removing the end of A/B/C deletes B, then eventually throws with one node left. PR #12822 passes the computed last index rather than the boolean flag and reports a focused regression test passing. Human approvals are not a merge; no packaged runtime was identified in the issue and no shipped fix was verified. <https://github.com/microsoft/microsoft-ui-xaml/issues/12821> · <https://github.com/microsoft/microsoft-ui-xaml/pull/12822>

- **Issue #12710 — unselected ComboBox opens halfway down.** New PR #12819 explains the mismatch: with more than 15 items and no selection, layout chooses the midpoint while keyboard focus targets off-screen item zero. The proposed fix anchors item zero and refreshes arrange before opening; author-reported tests cover selected/editable variants too. Open and unmerged. <https://github.com/microsoft/microsoft-ui-xaml/issues/12710> · <https://github.com/microsoft/microsoft-ui-xaml/pull/12819>

- **Issue #12355 — display-off memory proposal adds soft-suspend.** Fresh reviews question notification ordering and continued off-thread image uploads. The author revised PR #12765 to use the hidden-window path, including soft-suspend after two seconds. Synthetic VM memory/handle measurements improved, but **the original hardware WriteableBitmap leak and real monitor power-off remain unverified**; the new ordering test was not locally executed. Open, not shipped. <https://github.com/microsoft/microsoft-ui-xaml/issues/12355> · <https://github.com/microsoft/microsoft-ui-xaml/pull/12765>
