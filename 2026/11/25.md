## News/releases

- **Debug the manifest that actually ships.** Microsoft Inside MSIX, November 24, 09:00 PST. `Package.appxmanifest` is the editable template; build substitution generates `AppxManifest.xml`, which packaging consumes. The article demonstrates direct edits for elements without designer UI and stamping an output manifest from executable VERSIONINFO. For install/activation failures or CI packaging, inspect generated executable, entry-point and version values—not just the template. Guidance, not a new packaging fix. <https://devblogs.microsoft.com/insidemsix/package-appxmanifest-vs-appxmanifest-xml/>

- **Visual Studio November update: less repeated solution work.** Microsoft, November 24, 09:00 PST. The update describes reduced solution-close/file-watch/source-control overhead and MSBuild Restore from Open Folder for supported projects; **C++ `.vcxproj` is excluded**. Its XAML designer startup improvements are explicitly **UWP**, not WinUI 3 designer support, and cited Parse Solution improvements are not total-load or WinUI benchmarks. <https://devblogs.microsoft.com/visualstudio/visual-studio-november-update-faster-workflows-better-reviews/>

## microsoft-ui-xaml — past 24 hours

**Exact window: November 24, 08:31:28 → November 25, 08:31:28 PST.** All items below are Issues or issue-linked fixes, not GitHub Discussions.

- **Issues #12833 / #12832 — window-close retention gets concrete repros.** New November 24, 23:54–23:57 PST reports on SDK 2.6.5 describe recreated/stranded XamlRoot trees during unload and an extra activation-factory reference per island; the reporter counted ten retained roots after ten closes. Patched-DLL results combine changes; one factory path is code-analysis-only. Separately, new **WindowsAppSDK #7001** reports roughly 56 retained native handles per custom-titlebar window; private XAML patches reportedly did not change that result, so do not assume one cause. Measure native handles/composition resources in repeated-window tests. These are reporter diagnoses, **not upstream-confirmed or shipped fixes**. <https://github.com/microsoft/microsoft-ui-xaml/issues/12833> · <https://github.com/microsoft/microsoft-ui-xaml/issues/12832> · <https://github.com/microsoft/WindowsAppSDK/issues/7001>

- **Issue #12821 — TreeView fix moved from open proposal to merged source.** PR #12822 merged November 24, 21:25:57 PST. `RemoveAtEnd()` now passes the actual final index rather than a Boolean that selected index 1. This materially updates yesterday's report; **no package shipment verified**. <https://github.com/microsoft/microsoft-ui-xaml/issues/12821> · <https://github.com/microsoft/microsoft-ui-xaml/pull/12822>

- **Issue #12772 — transformed ImageBrush decoding fix merged.** PR #12777 merged November 24, 21:50:09 PST, accounting for enlarging brush-transform scale when selecting bitmap decode size. Rotation/rasterization follow-ups remain in #12807. The associated closure of older radius/memory issue #8907 does **not** prove that separate memory complaint fixed; stated tests leave those cases unchanged. Source merge, not shipment. <https://github.com/microsoft/microsoft-ui-xaml/issues/12772> · <https://github.com/microsoft/microsoft-ui-xaml/pull/12777> · <https://github.com/microsoft/microsoft-ui-xaml/issues/12807>

- **Issue #12148 — zero-viewport LinedFlowLayout crash has a candidate.** New PR #12826 preserves unfrozen ranges and forces relayout when no lines are frozen. The author reports old-build crash reproduction and 14/14 suite passes after the change. **Still open**; tests were not independently run here. <https://github.com/microsoft/microsoft-ui-xaml/issues/12148> · <https://github.com/microsoft/microsoft-ui-xaml/pull/12826>

- **Issue #12828 — failed resource compilation can poison retries.** Newly reported November 24: failed `rc.exe` execution can leave fresh `.rc` text alongside stale `.res`, allowing a retry to silently emit old PE version fields. PR #12829 proposes a successful-compilation stamp, reports 20 passing fixture cases and has human approval, but **remains open**. A build-metadata recovery issue, not rendering. <https://github.com/microsoft/microsoft-ui-xaml/issues/12828> · <https://github.com/microsoft/microsoft-ui-xaml/pull/12829>
