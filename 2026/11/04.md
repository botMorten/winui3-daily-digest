## Community experience

- **On-demand MSIX languages: installation versus activation.** WindowsAppSDK Discussion, November 3; self-answer November 4. A developer says `AddResourcePackageAsync` appeared to install a language outside Windows’ preferred list, yet the app could not resolve its resources. Their self-answer recommends forcing target-app shutdown and applying updates; they also report the app did not automatically restart. This is a single-reporter workaround, not a maintainer-confirmed fix—test the complete language-switch/relaunch flow, not merely installation success. <https://github.com/microsoft/WindowsAppSDK/discussions/6933#discussioncomment-19395815>

- **Catch-up: AMD support reaches Microsoft’s Aion WinUI sample.** Microsoft sample PR merged November 2. The WinUI 3 on-device inference sample now accepts AMD Ryzen AI through VitisAI alongside Qualcomm and Intel; the PR author reports hardware validation. AMD requires framework 1.1.0.2 or newer and SDK NuGet 1.1.1; there is no CPU fallback. Useful integration reference, with a large boundary: this validation package explicitly must not ship to end users, and its displayed streaming measurements are not tokenizer-throughput benchmarks. <https://github.com/microsoft/Aion-Instruct-Preview-Sample/pull/16>

## News/releases

- **WinApp VS Code v0.4: project-aware XAML IntelliSense preview.** Microsoft #ifdef Windows, November 3. Completion understands custom controls, properties, events and resources; semantic diagnostics include invalid `x:Bind` paths, with C# navigation and XAML-name/resource rename support. Full project awareness requires the .NET 10 SDK and C# WinUI on Windows x64/ARM64; C++/WinRT currently gets basic editing and syntax diagnostics, not equivalent IntelliSense. New project creation and project/solution build-run/F5 support reduce editor-to-terminal juggling. The extension is released; the XAML feature remains experimental. <https://devblogs.microsoft.com/ifdef-windows/xaml-intellisense-support-in-winapp-extension/>

- **PowerToys adopts newer UI dependencies in a development preview.** v0.103.3062.0, published November 3 Pacific. This prerelease updates Windows App SDK to **2.6.4**, Win2D to 1.4.0 and WebView2, including Command Palette template references. It is a concrete adoption/integration reference—not a recommendation to choose 2.6.4 over already-reported 2.6.5, nor evidence that today’s reported framework bugs are resolved. <https://github.com/microsoft/PowerToys/releases/tag/v0.103.3062>

## microsoft-ui-xaml — past 24 hours

Exact window: **November 3, 2026, 08:30 PST → November 4, 2026, 08:30 PST**. All entries below are **Issues**, not Discussions.

- **Surface redraws reportedly accumulate GPU memory — new November 4.** In #12540, a 2.6.5 repro redraws 100 small composition surfaces at 60 Hz. The author reports approximately 930 MB/s growth during UI-thread stalls, retained GPU allocations afterward, and slower growth without stalls through both Win2D and raw interop. `RequestCommitAsync` is mentioned as a consumption signal, not a validated general fix. Relevant to animated stickers/video thumbnails; independently reproduced root cause and resolution are absent. <https://github.com/microsoft/microsoft-ui-xaml/issues/12540>

- **External UIA inspection still crashes a visible window, reporter says — new November 3 comment on a June issue.** #11139 now contains a packaged 2.6.5 repro involving another process walking UIA and reading `BoundingRectangle`, ending in a wrong-thread fail-fast. Accessibility tools and desktop automation clients are the practical exposure; this remains a contributor report, not a maintainer-confirmed diagnosis. <https://github.com/microsoft/microsoft-ui-xaml/issues/11139#issuecomment-6611460568>

- **Missing CJK IME candidates isolated to unpackaged deployment — new November 4.** #12554 reports failure on Windows build 26300.9818 with both SDK 2.6.4 and 1.6, while the same binary registered as MSIX works. The reporter says external-location package registration restores candidates. Treat this as a build-specific, unconfirmed workaround—not a new universal packaging requirement. <https://github.com/microsoft/microsoft-ui-xaml/issues/12554>

- **Useful upgrade result for missing UIA property-change events — November 3 activity on a July 2025 issue.** In #10645, dotMorten reports reproducing the problem and finding it disappears on SDK 1.8.0 (`1.8.250907003`) or newer; the issue was closed. This is fresh verification of an older version boundary, not a newly shipped fix or a resolution of the separate UIA crash above. <https://github.com/microsoft/microsoft-ui-xaml/issues/10645#issuecomment-6618830676>

- **Chart testing exposes accessibility and allocation edges — new November 4.** #12547 reports date points announced as ordinals; another participant corroborates missing dates through UIA properties in two synthetic configurations. This concerns an experimental review build. Separately, #12550 reports roughly one million requested tick intervals driving a five-point chart past a 700 MiB watchdog; the watchdog terminated it, so this is not a demonstrated natural OOM. No confirmed fixes. <https://github.com/microsoft/microsoft-ui-xaml/issues/12547> · <https://github.com/microsoft/microsoft-ui-xaml/issues/12550>
