## News/releases

- **Catch-up: UWP ink migration has concrete API gaps, not just renamed namespaces.** Microsoft Learn, dated October 13; updated October 14: <https://learn.microsoft.com/en-us/windows/apps/develop/ai-assisted/migrate/uwp-to-winui#ink-win2d-and-printing>. The guide documents that 2.5.4-experimental has no public `InkStrokeContainer` constructor and a read-only `InkPresenter.StrokeContainer`; its suggested way to switch stroke sets is saving and loading them, with no save/load progress reporting. It also warns that eraser APIs exposed in 2.4.1-experimental were removed in 2.5.4-experimental, and shows aliases to avoid ambiguous ink-type names across namespaces. These are practical porting constraints—not a new release or evidence of completed app adoption—and built-in inking remains experimental rather than a stable-channel replacement.

No new Windows App SDK release was found in the directly inspected GitHub release list: <https://github.com/microsoft/WindowsAppSDK/releases>. The official Windows Developer and #ifdef Windows blog listings yielded no new relevant announcement; Gallery 3.0 was already covered.

## microsoft-ui-xaml — past 24 hours

**Exact window:** October 17, 2026, 08:30 PDT → October 18, 2026, 08:30 PDT.

- **Queued Flyouts: the theme-change crash now has a merged source fix.** Issue [#12089](<https://github.com/microsoft/microsoft-ui-xaml/issues/12089>) opened September 29; [PR #12308](<https://github.com/microsoft/microsoft-ui-xaml/pull/12308>) merged to `main` October 17 at 21:02 PDT, and the issue closed moments later. When a second Flyout is staged while another closes, its presenter may not exist yet; the inspected patch guards theme forwarding against that missing presenter. Its regression test stages the Flyout, changes Light→Dark, then verifies the eventual presenter receives Dark. This materially advances the previously reported prewarming workaround, but **source merged is not a shipped fix**: no Windows App SDK package containing the commit was established, and tests were not independently executed here.
