## Community experience

- **Windows AI watermark accessibility report gets a Microsoft response.** WindowsAppSDK issue, opened November 4; new replies November 12. Updating earlier coverage: a Microsoft contributor acknowledged that watermark characters can become “non-invisible” and affect applications, said mitigation options are being explored, and pointed developers to existing watermark documentation. The reporter’s concrete problem is interrupted braille/screen-reader output from generated image descriptions; their follow-up asking whether removal violates terms remains unanswered. This is acknowledgment, not a shipped fix or blanket permission to strip provenance markers. If your WinUI app displays Windows AI output, test assistive-technology behavior as well as visual rendering. <https://github.com/microsoft/WindowsAppSDK/issues/6936#issuecomment-6830099276>

## News/releases

- **PowerToys’ newest development preview consumes Windows App SDK 2.6.5.** PowerToys v0.103.3151, published November 12 PST (November 13 UTC). Unlike the previously covered 2.6.4-based preview, this release includes the 2.6.5 package upgrade, CsWinRT 2.3.1 and Windows SDK .NET reference pack 10.0.26100.87. It also adds native bar-chart rendering to extension-supplied Command Palette Adaptive Cards—a concrete extension experience, not evidence that WinUI’s experimental Chart control has become stable. Useful source material for teams planning dependency upgrades; this remains a **PowerToys development preview**, not a stable PowerToys release or a newly released SDK. <https://github.com/microsoft/PowerToys/releases/tag/v0.103.3151>

- **Catch-up: a practical Store-submission checklist for packaged WinUI apps.** Microsoft Learn, dated/updated November 10. The checklist brings together package identity/version matching, runtime prerequisites, clean-machine installation, certification, keyboard/screen-reader checks and Store listing requirements. Two easy-to-miss details: packaged WinUI 3 desktop apps need a privacy-policy URL even when they collect no personal data, and Store distribution does not require buying your own signing certificate. This is consolidated guidance, not a newly announced Store policy. <https://learn.microsoft.com/en-us/windows/apps/publish/store-readiness-checklist>

## microsoft-ui-xaml — past 24 hours

**Exact window:** November 12, 2026, 08:30 PST → November 13, 2026, 08:30 PST.

- **Issue: ItemsRepeater can retain a moved, focused row and then fail keyed Reset.** New November 13, 05:08 PST. Kenny Kerr supplied a Windows App SDK 2.6.4 C# reproduction: focus a row, scroll it out so it remains pinned, reorder the collection, then reset it. The reported result is duplicate displayed rows followed by “The unique id provided (2) is not unique.” Switching notifications to `Move` or `Remove`/`Add` avoids the exception but still produces wrong rows, so it is **not a complete workaround**. Practical implication: test virtualized collection reordering with offscreen keyboard focus, not just pointer-driven visible rows. No WinUI fix was verified. <https://github.com/microsoft/microsoft-ui-xaml/issues/12659>
  - **Related, narrowly scoped progress:** windows-rs PR #5378 merged at 05:50 PST November 13. It propagates the ItemsRepeater handler failure instead of letting the Rust Reactor implementation continue with corrupted rows. That is a diagnostic/fail-fast improvement, **not an ItemsRepeater repair or verified package release**. <https://github.com/microsoft/windows-rs/pull/5378>

- **Issue: ListView’s Extended-selection crash gets a proposed fix.** Original issue from September 2024; new public patch linked November 12, 10:17 PST. PR #12649 identifies deselection mutating the live `ISelectionInfo.GetSelectedRanges` collection while it is being traversed; the inspected patch snapshots the range references before deselection. It includes regression tests for replacing selection, clearing selection and clicking an already-selected item. This is tangible progress for custom/virtualized selection implementations, but the PR remains **open, not merged or shipped**, and its reported tests were not independently executed. <https://github.com/microsoft/microsoft-ui-xaml/issues/10025> · <https://github.com/microsoft/microsoft-ui-xaml/pull/12649>
