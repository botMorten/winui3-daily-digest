## Community experience

- **OpenNet showcases a native C++/WinRT download client.** Author announcement, **October 5, 04:39 PDT**. The project combines WinUI 3 with libtorrent and aria2 for torrent/magnet and HTTP downloads, RSS subscriptions and download-management UI; its README links a Microsoft Store listing and targets Windows 11 ARM64/x64. The author explicitly calls it experimental and incompletely tested: useful adoption evidence, not proof of production reliability or superior performance. <https://github.com/microsoft/microsoft-ui-xaml/discussions/12165> · <https://github.com/hoshiizumiya/OpenNet>

- **HLSL and liquid-glass controls come with a significant support boundary.** Author announcement, **October 5, 04:29 PDT**. `WinUI.Composition.Hlsl` exposes custom shader effects through Composition and XAML brushes, with a companion native control library and claimed x86/x64/ARM64 support. Crucially, the repository says shader execution relies on a **private, undocumented Composition ABI**; its advertised fail-closed checks and preserved native layout/input/UI Automation semantics are project claims, not Microsoft compatibility guarantees. Interesting graphics work, but assess that dependency before shipping. <https://github.com/microsoft/microsoft-ui-xaml/discussions/12164> · <https://github.com/Millennium-Science-Technology-R-D-Inst/WinUI.Composition.Hlsl>

## News/releases

- **Catch-up: WinApp CLI 0.7.1 cleans up AOT output—and changes project-context telemetry classification.** Release **October 1, 15:54 PDT**, not today's news. `winapp run --aot` now streams publish progress without dumping MSBuild property JSON; the implementation uses MSBuild 17.10's result-file support, making **.NET SDK 8.0.300+** the documented minimum for this path. Another change classifies the existing bounded project-context event as Critical so it can reach telemetry with diagnostics disabled; the PR says payload and opt-out remain unchanged, with `WINAPP_CLI_TELEMETRY_OPTOUT=1` preventing project-context inspection/emission. This is CLI servicing, not a WinUI runtime update. <https://github.com/microsoft/winappCli/releases/tag/v0.7.1> · <https://github.com/microsoft/winappCli/pull/936> · <https://github.com/microsoft/winappCli/pull/940>

## microsoft-ui-xaml — past 24 hours

**Exact window: October 4, 08:30 PDT → October 5, 08:30 PDT.** Direct authenticated API inspection covered all-state Issues and enabled GitHub Discussions; PRs were excluded from issue counts. The two project announcements above are not repeated here.

- **Discussion: inking gets a complete note-app example.** New **October 5, 08:27 PDT**. Team WinUI demonstrates `InkCanvas`, `InkToolbar`, pen/pencil/highlighter tools and saving a GIF with embedded ISF so strokes remain editable when reloaded. This directly addresses a UWP-to-WinUI migration gap and supplies full sample code; availability is explicitly **2.5.4-experimental**, not stable shipment. <https://github.com/microsoft/microsoft-ui-xaml/discussions/12168>

- **Issues: hidden/minimized animations keep working, while visibility events miss hide/show.** Both new **October 4, 18:56–18:57 PDT**. One reporter supplies tests across 2.4.0, 2.5.1 and 2.5.4-experimental, describing compositor CPU use from active indeterminate controls and `Window.VisibilityChanged` not matching changes to `Window.Visible`. Suggested mitigation: deactivate/collapse animations and observe `AppWindow.Changed` visibility changes; neither report has a maintainer-confirmed framework fix. <https://github.com/microsoft/microsoft-ui-xaml/issues/12159> · <https://github.com/microsoft/microsoft-ui-xaml/issues/12160>

- **Issue: WebView2 activation can miss DLLs registered with `AddDllDirectory`.** New **October 4, 12:38 PDT**. The PyWinRT reporter attributes `0x8007007E` and possible initialization hangs to legacy DLL-search behavior, contrasting affected 2.x runtimes with working 1.7/1.8. A same-day downstream commit adds a preload mitigation; that is not a WinUI fix or verified released PyWinRT package. <https://github.com/microsoft/microsoft-ui-xaml/issues/12158> · <https://github.com/pywinrt/pywinrt/commit/8de9ad4493c96e7b261217d181357c496af434ca>

- **Issue update: `TransformToVisual` now has the requested minimal sample.** Original **October 3**; new reply **October 4, 11:36 PDT**. Following yesterday's non-reproduction/sample request, the reporter measures approximately **59.9 MB** additional process heap after 100,000 calls and forced GC, against a near-zero `ActualOffset` control. This strengthens the reproduction evidence, but remains a reporter measurement—not independent confirmation or a resolved leak. <https://github.com/microsoft/microsoft-ui-xaml/issues/12156#issuecomment-5983131470>

- **Issue update: C++/WinRT array code generation gets a proposed correction.** Original **September 14, 2022**; new linked-PR activity **October 5, 05:21 PDT**. A Microsoft member's PR addresses `com_array<T>` projection and Guid/Char mappings with regression tests. It was verified **open and unmerged**: useful progress for affected IDL authors, not a shipped fix. <https://github.com/microsoft/microsoft-ui-xaml/issues/7726> · <https://github.com/microsoft/microsoft-ui-xaml/pull/12167>

- **Discussion plus issue follow-up: theme-aware caption tooltips as a community solution.** New **October 4, 22:13–22:17 PDT**. HO-COOH presents an acrylic, theme-aware caption-button tooltip and links it from the existing dark-tooltip proposal. It is a WinUIEssentials implementation, not first-party servicing; evaluate the library if that visual inconsistency affects your app. <https://github.com/microsoft/microsoft-ui-xaml/discussions/12161> · <https://github.com/microsoft/microsoft-ui-xaml/issues/11802#issuecomment-5988564282>
