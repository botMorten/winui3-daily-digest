## Community experience

- **Resetting the language override reportedly crashes packaged apps.** WindowsAppSDK issue, opened November 25: <https://github.com/microsoft/WindowsAppSDK/issues/7003>. The reporter says assigning `null` or an empty string to `Microsoft.Windows.Globalization.ApplicationLanguages.PrimaryLanguageOverride` crashes a packaged 2.7.0 app, unlike the corresponding `Windows.Globalization` API. Related <https://github.com/microsoft/WindowsAppSDK/pull/6878> proposes empty-string reset and persistent storage for packaged apps; November 26 review still requests stronger activation, resource-lookup and process-restart tests. Developers offering “return to system language” should treat this as an unresolved report, not assume the proposed fix is available.

- **Portable WinUI distribution exposes an unanswered licensing question.** WindowsAppSDK Discussion, originally October 7; substantive November 23 follow-up, newly covered today: <https://github.com/microsoft/WindowsAppSDK/discussions/6847#discussioncomment-19834635>. A Fibonacci app developer distributing an unpackaged, self-contained WinUI 3/SDK 2.7.0 ZIP asks whether bundling Microsoft terms and notices is sufficient or affirmative end-user/downstream acceptance is required. No Microsoft answer was found. This illustrates a real deployment uncertainty; it is neither a new licensing rule nor legal guidance.

## microsoft-ui-xaml — past 24 hours

**Exact window:** November 25, **08:31:25 PST** → November 26, **08:31:25 PST**. Issues and Discussions checked directly through read-only GitHub REST/GraphQL, including older threads’ comments/replies and meaningful linked-source events.

- **Display-off surface buildup: fix merged.** Issue <https://github.com/microsoft/microsoft-ui-xaml/issues/12355>, originally October 20; <https://github.com/microsoft/microsoft-ui-xaml/pull/12765> merged November 26 at **00:55 PST**. Display-off now uses the hidden-window/suspend path to stop rendering/uploads and resumes with current bitmap content. The author’s earlier test reported uploads dropping from 1,793 to one over 40 seconds, but actual monitor-power-off hardware testing was not established. Today’s change is the merge—not a newly measured result or shipped fix.

- **ContentPresenter exit-transition crash: targeted fix landed.** Issue <https://github.com/microsoft/microsoft-ui-xaml/issues/11047>, originally March 27; <https://github.com/microsoft/microsoft-ui-xaml/pull/12820> merged at **06:02 PST**. The diagnosed trigger is a presenter reattaching its own still-unloading Page, rather than NavigationView itself. The patch cancels that exit transition before reattachment; the author reports a red/green test and five crash-free sample rounds. Connected/implicit-animation-held elements remain outside this fix’s scope. Source-only, with no package shipment verified.

- **NavigationView selection cleanup: broader than the old null case.** Issue <https://github.com/microsoft/microsoft-ui-xaml/issues/8266>, originally March 9, 2023; <https://github.com/microsoft/microsoft-ui-xaml/pull/12542> merged at **06:10 PST**. The new change clears stale child-selection visuals for an item outside the menus and cancels a pending overflow move after selection clears. The original null-assignment path had already been addressed separately. Despite wording in the PR description, the final diff does **not** add a new `OnFlyoutClosing` null guard; that should not be credited to this merge.

- **Unselected ComboBox popup: candidate became a merge.** Issue <https://github.com/microsoft/microsoft-ui-xaml/issues/12710>, originally November 16; <https://github.com/microsoft/microsoft-ui-xaml/pull/12819> merged at **03:41 PST**. Long lists with `SelectedIndex == -1` now anchor at the first item instead of the midpoint; reopening also discards stale arrangement/scroll positioning. The author reports focused tests passing. Practical improvement for unselected dropdowns, but still a main-branch fix rather than a verified shipping update.

- **Stowed-exception debugging instructions hit a dead download.** New issue November 25 at **19:19 PST**: <https://github.com/microsoft/microsoft-ui-xaml/issues/12851>. The reporter says `.load pde` fails despite documentation claiming modern WinDbg includes PDE. Contributor riverar supplied a temporary PDE v11.3 attachment at **19:37 PST**. That is a suggested recovery, not an independently validated download; no attachment was downloaded or executed, and the documentation issue remains open.

- **Source-build instructions still fail on retest.** Issue <https://github.com/microsoft/microsoft-ui-xaml/issues/11696>, originally August 28, gained a fresh contributor retest November 25 at **15:28 PST**: <https://github.com/microsoft/microsoft-ui-xaml/issues/11696#issuecomment-7177601426>. Riverar says the current instructions still leave initialization and building broken, with screenshots. This is new reproduction evidence on existing tooling pain, not proof of a new regression or a resolved build path.
