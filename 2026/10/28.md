## Community experience

- **TypeWhisper adds another local speech engine without pretending a daily is stable.** GitHub, October 28 release; implementation merged October 27. The WinUI 3 app’s latest 1.3 daily includes a Voxtral Mini 4B plugin using a resumable 2.8 GB model download and Vulkan acceleration, with CPU fallback and an explicit performance warning. Despite the model’s “Realtime” name, this integration transcribes **after recording ends**, not live streaming. It is a concrete native-app/plugin example; the project separately maintains its 1.2 stable branch, and Windows ARM64 remains untested x64 emulation, not a native build. No independent runtime testing performed. <https://github.com/TypeWhisper/typewhisper-win/releases/tag/v1.3.0-daily.20261028.139> · Implementation: <https://github.com/TypeWhisper/typewhisper-win/pull/723>

- **Catch-up: accessibility handoff can now speak WinUI 3 rather than generic web semantics.** Aaron Gustafson, October 22. Accessibility Assistant for Figma v53 adds a Windows WinUI 3 target alongside distinct Win32/WPF targets; platform selection changes available annotations and focus-order calculations, including arrow-key/internal navigation. Projects combine annotations, assessment progress and issues, then export HTML or Markdown specs for engineers. The practical gain is recording intended initial focus and keyboard order before implementation—not a claim that exported specs or automated design checks prove the finished app accessible. <https://www.aaron-gustafson.com/notebook/accessibility-assistant-for-figma-v53/>

## News/releases

- **Windows App SDK 2.6.4 ships reliability and tooling repairs.** Microsoft, October 27; GitHub release published 14:14 PDT. Official stable notes list fixes for shutdown access violations with surviving text controls, ItemsView scrolling toward collapsed/recycled targets, and WebView2 receiving focus while initialization finishes with a disabled parent. DispatcherQueue callbacks and timer handlers now retain original exception details in crash dumps; self-contained apps get a missing Insights resource-DLL repair. VS Code/C# Dev Kit users also get a fix for false errors on `InitializeComponent` and named XAML fields, with `EnableWinUIDesignTimeGeneratedXamlCompileItems=false` as the opt-out. These are **officially released fixes**, not independently reproduced results, and do not imply every recent main-branch change shipped. The release also removes the Language Model LAF-unlock requirement for apps using this version; older SDKs retain their requirements. <https://github.com/microsoft/WindowsAppSDK/releases/tag/v2.6.4>

## microsoft-ui-xaml — past 24 hours

**Exact window: October 27, 08:30–October 28, 08:30 PDT.** Issues and Discussions checked directly, including older threads’ new comments/replies.

- **New hybrid-GPU report: wrong text in the right controls.** Issue #12434, opened October 28. A business-app developer reports that a blank WinUI app on **2.6.4** corrupts glyphs/fills when resized on a display attached to a different GPU than the app uses; Live Visual Tree values remain correct. Moving back to the primary display restores rendering; matching the app’s GPU preference to the external display’s GPU reportedly prevents it, with battery/deployment tradeoffs. A contributor suggests an existing adapter-change PR might help, but it remains open and applicability is unproven. **New report, not a confirmed regression or fix.** <https://github.com/microsoft/microsoft-ui-xaml/issues/12434>

- **Experimental TableView exposes consequential accessibility gaps.** New October 28 issues #12443/#12444 report retained UI Automation elements silently switching to another group or row after scrolling/filtering—so subsequent collapse/select operations target the wrong item. #12445 reports missing UIA selection for a never-realized offscreen row; #12457 identifies virtualized group-header lookup failures. These are concrete human repros affecting screen readers and test automation, not merely bot diagnoses. The lookup repair is an **open proposal**, not a fix for every related case; stable-release impact is not established. <https://github.com/microsoft/microsoft-ui-xaml/issues/12443> · <https://github.com/microsoft/microsoft-ui-xaml/issues/12444> · <https://github.com/microsoft/microsoft-ui-xaml/issues/12445> · <https://github.com/microsoft/microsoft-ui-xaml/issues/12457>

- **Compiler clarification: one cache bug fixed in source does not mean all are.** October 27–28 responses on older #12334/#12104 distinguish timestamp-triggered repeated XBF generation from stale output after changing `NoPageCodeGen`/`NoTypeInfoCodeGen`. A contributor confirms the timestamp repair already merged **October 10**; the other author explains why generation-flag invalidation remains unresolved. This is fresh clarification, not a new merge or verified package shipment—important when diagnosing stubborn incremental builds. <https://github.com/microsoft/microsoft-ui-xaml/issues/12334#issuecomment-6454436269> · <https://github.com/microsoft/microsoft-ui-xaml/issues/12104#issuecomment-6460695476>

- **Older runtime-crash investigation gets recovery evidence, not a root cause.** Issue #12169, opened September 30; new October 27–28 exchange. A team member suggests runtime repair or updating; repair reportedly fails because resources are in use. The reporter subsequently confirms inbox apps **and the framework-dependent test app** recover after reboot, still working after removing the earlier `ForcePerfOptIn=0` override. Locale files were untouched. Do not read this as proof repair succeeded or 2.6.4 cured the problem; the recovery’s cause remains unknown. <https://github.com/microsoft/microsoft-ui-xaml/issues/12169#issuecomment-6462083436>
