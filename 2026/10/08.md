## Community experience

- **Custom title bars can leave native resources behind after window closure.** Windows App SDK issue, **October 8**: <https://github.com/microsoft/WindowsAppSDK/issues/6848>. A developer reports roughly 35 additional handles and 2–3 MB of private memory per open/close cycle in an unpackaged, self-contained WinUI 3 app using WinUI 2.3.9 / InteractiveExperiences 2.1.9; their debugger traces point to native title-bar composition resources not being torn down. Their tested mitigation is to set `ExtendsContentIntoTitleBar = false`, call `AppWindow.TitleBar.ResetToDefault()`, then close; reusing one window with Show/Hide also avoided the reported accumulation. Particularly relevant to long-running tray apps that repeatedly open settings windows: these are reporter measurements and workarounds, **not a maintainer-confirmed diagnosis or shipped fix**, and a smaller baseline leak remains in their test.

- **Catch-up: Console Mode’s WinUI migration now has a substantial stable 1.6 release.** Project release, **October 6**: <https://github.com/lippdev/consolemode/releases/tag/v1.6.0>. Beyond the previously covered migration/alpha, the shipped app adds controller-first Home/Session/System navigation, a fullscreen window-switching overlay and ControlFS integration; release notes say controller focus no longer gets stuck between columns or tabs. The tagged project confirms WinUI 3, Windows App SDK 1.7 and self-contained deployment, with installer and portable-single-EXE downloads—a concrete adoption example rather than another framework promise; releases remain unsigned, so the project warns about SmartScreen/antivirus prompts.
