## Community experience

- **RibbonSpace 1.1.0 brings an Office-style ribbon to plain WinUI 3** — Wiesław Šoltés / GitHub, **Oct 3 UTC (Oct 2 PDT)**. `RibbonSpace.WinUI` shares controls, MVVM, themes, KeyTips and backstage code with the Uno version, but **does not require Uno**. The port documents explicit namespaces, separate theme dictionaries, subclass style keys and PRI/XBF packaging; the author reports x64 CI and ARM64-VM runtime tests. For opaque XAML compiler failures, its diagnostic workaround is Visual Studio MSBuild with `UseXamlCompilerExecutable=false`. <https://github.com/wieslawsoltes/RibbonSpace/releases/tag/v1.1.0> · <https://github.com/wieslawsoltes/RibbonSpace/blob/main/docs/winui-differences.md>

- **Energy Saver debate: fix the old contract, or make apps migrate?** — WindowsAppSDK Issue, **May 15; comments Oct 2**. Two developers added three comments arguing that the existing on/off API should report On whenever Energy Saver is active, rather than require `EnergySaverStatus2`; one needs the underlying Win32 notification fixed. Standard mode appearing as Off affects throttling background work, but the comments establish neither a maintainer decision nor a shipped fix. <https://github.com/microsoft/WindowsAppSDK/issues/6483#issuecomment-5960930527>

## News/releases

- **Catch-up: MSTest/MTP guidance for unpackaged WinUI testing** — Microsoft Learn, **Sept 30; updated Oct 1**. Packaged, unpackaged and AppContainer hosts require MSTest **4.5** and Microsoft.Testing.Platform **2.5** for the full matrix, using matching previews until stable versions ship. MTP can launch an unpackaged executable directly: publish the dispatcher for `UITestMethod`, propagate the exit code and close the app so unattended runs finish. `WindowsAppSDKSelfContained=true` bundles the SDK runtime, **not** the .NET Desktop Runtime. <https://learn.microsoft.com/en-us/dotnet/core/testing/unit-testing-mstest-winui>

- **Catch-up: MSIX extension updates move to Visual Studio Installer** — WindowsAppSDK Discussion, **Sept 28; clarification Oct 1**. The Marketplace extension remains usable but frozen; Installer-managed WinUI components receive future updates and take precedence without uninstalling it. The maintainer named **VS 2026 18.12 Insiders 1**, with stable **18.12** planned subject to validation—not confirmed availability. Existing Installer-managed users need no migration; project/debug settings remain. <https://github.com/microsoft/WindowsAppSDK/discussions/6813#discussioncomment-18701913>

## microsoft-ui-xaml — past 24 hours
**Exact rolling window:** October 2, **13:57:00 PDT** → October 3, **13:57:00 PDT**. Entries are Issues, not Discussions or a PR changelog.

- **Update: LinedFlowLayout crash is not established as a new 2.5 regression.** #12148, filed **Oct 2 PDT**, gained **one Oct 3 comment** with a minimal repro and Copilot-assisted contributor testing. Controlled width changes at zero viewport reportedly crash ARM64 packages from **1.8.0 through 2.5.4-experimental**; the C# image-loading port did not reproduce the original C++ race. Crucially, `Loaded` plus low-priority enqueue still crashed; assigning items only after observing a positive viewport survived the contributor's limited tests. This supersedes the morning's suggested deferral, not a maintainer-confirmed or shipped fix. <https://github.com/microsoft/microsoft-ui-xaml/issues/12148#issuecomment-5973306510>

- **New: TransformToVisual native-memory growth.** #12156, **Oct 3**, reports roughly **600 bytes per call** on unpackaged C# / SDK **2.4.0**: around 59 MB after 100,000 calls, persisting after GC and idle time. The reporter identifies native transform objects in a heap census; repeated row-position calculations could amplify the impact. No replies, confirmed workaround or fix. <https://github.com/microsoft/microsoft-ui-xaml/issues/12156>

- **Popup work-area limits: usable workaround, substantial complexity.** #11945 (**Sept 19**) has **four in-window comments from two participants**: a zero-sized topmost window hosting a XAML island with `ShouldConstrainPopupsToWorkArea=false`, versus objections to island complexity and arguments for reduced mouse travel/accessibility. The related prototype remains open and “do not merge,” not shipped. <https://github.com/microsoft/microsoft-ui-xaml/issues/11945#issuecomment-5962804286>

- **Async XAML proposal: background compilation, UI-thread construction.** #12142 (**Oct 2**) has **one comment in this revised window**, proposing background XBF compilation followed by UI-thread loading. The morning's earlier comment discussed thread affinity. Neither establishes an implemented `LoadAsync`, measured speedup or maintainer commitment. <https://github.com/microsoft/microsoft-ui-xaml/issues/12142#issuecomment-5965216294>

- **Slider steps with nonzero Minimum.** #12153, **Oct 3**, reports **2.4.0** selecting even intermediate values with `Minimum=1`, `Maximum=31`, `StepFrequency=2`, rather than odd values anchored to Minimum. Test allowed values before relying on this configuration; no comments or confirmed fix. <https://github.com/microsoft/microsoft-ui-xaml/issues/12153>
