## Community experience

- **.NET 11 migration revives a Native AOT/MSIX packaging headache.** WindowsAppSDK issue, originally March 27; new reporter follow-up November 15 Pacific. After an October preview fix had worked for the reporter, switching from .NET 10 to .NET 11 with MSIX BuildTools `1.7.261102100` reportedly produces a duplicate `WinRTCOMServer.pdb` payload error. Disabling Native AOT on the COM server works **for that reporter**. Test multi-executable packages before upgrading: the issue remains closed, with no fresh maintainer confirmation or verified fix for this recurrence. <https://github.com/microsoft/WindowsAppSDK/issues/6353#issuecomment-6907240385>

- **Separate ARM64 F5 blocker: missing debug VCLibs.** WindowsAppSDK issue, November 15 Pacific. A developer using WinUI `2.6.5` and Visual Studio 2026 `18.12.0` reports `DEP0700`/`0x80073CF3`: deployment cannot find `Microsoft.VCLibs.140.00.Debug.UWPDesktop`, minimum `14.0.33728.0`. This prevents debugging before the app starts, rather than failing during Native AOT publishing. Only automated triage was present; no verified workaround. The dependency's “UWPDesktop” name does not make the application UWP. <https://github.com/microsoft/WindowsAppSDK/issues/6976>

## microsoft-ui-xaml — past 24 hours

**Exact window:** November 15, 2026, 08:30 PST → November 16, 2026, 08:30 PST. - **Image URI locking: confirmed workarounds, no framework fix.** Issue #633, opened April 2019; new November 15 Pacific comments. A project contributor explains that `ms-appdata` image loading retains a memory-mapped file for the `BitmapImage` lifetime, preventing overwrite. They report verifying that a `file://` URI to the same file or `BitmapImage.SetSourceAsync` avoids the lock. Copying bytes would remove the lock but increase private memory per live image, so the proposed change was declined. Another participant asks for an option to choose the behavior. Practical implication: change the loading path when images must remain writable; don't expect a forthcoming automatic fix. <https://github.com/microsoft/microsoft-ui-xaml/issues/633#issuecomment-6907257712>

- **Native AOT + MSIX: project advice did not resolve the reporter's failure.** Issue #12670, opened November 15 Pacific. Either feature alone reportedly works, but together publishing fails manifest validation. Microsoft-member guidance covered newer MSIX tools, packaging properties and unconditional `PublishAot`; the reporter explicitly says the suggested property/tool update did **not** help. Participants also clarified that normal F5 builds differ from actual AOT publishes, and warned that dynamic-code/trimming problems can still surface only after publishing. Despite the issue's closed status, this is not a verified resolution. <https://github.com/microsoft/microsoft-ui-xaml/issues/12670#issuecomment-6903898462>

- **Ten Chart fixes announced for the next experimental release.** Issues originally filed November 4–5; new November 16 Pacific closure comments. Highlights: excessive `LinearAxis.Spacing` subdivisions will be rejected above 1,000 major intervals; Narrator will announce full dates rather than point positions; RTL charts will retain readable, non-mirrored text. Other closures address clipping, contrast, labels, themes and extreme geometry. These are concrete implementation claims with an **upcoming experimental** release target—not proof of shipped or stable fixes. <https://github.com/microsoft/microsoft-ui-xaml/issues/12550#issuecomment-6913135187> · <https://github.com/microsoft/microsoft-ui-xaml/issues/12547#issuecomment-6913127763> · <https://github.com/microsoft/microsoft-ui-xaml/issues/12570#issuecomment-6913143226>

- **Teardown crash gets stronger diagnostic evidence.** Issue #11228, opened July 8; new November 15 Pacific report. A developer supplies matching production dumps and a Page Heap reproduction in a packaged MAUI app using Windows App SDK 1.8. Their analysis identifies a surviving `SurfaceImageSource` peer whose controlling Win2D `CanvasImageSource` object was already freed. This is relevant to WinUI/Win2D lifetime debugging, but the evidence comes from that MAUI application—not a demonstrated failure in every WinUI app, nor a maintainer-confirmed root cause or fix. <https://github.com/microsoft/microsoft-ui-xaml/issues/11228#issuecomment-6910382379>

- **Trim-warning advice leads to another compiler error.** Issue #12708, November 16 Pacific. On `2.6.6-experimental`, a developer reports that WMC1510 recommends `x:SuppressXamlTrimWarnings`, but adding it produces XLS1102 and WMC0612/XBF “Property Not Found.” A minimal XAML example is supplied; no confirmed workaround or fix yet. <https://github.com/microsoft/microsoft-ui-xaml/issues/12708>
