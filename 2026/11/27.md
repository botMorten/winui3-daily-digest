## Community experience

- **Single-file publishing: a useful PRI workaround, not a universal resource fix.** WindowsAppSDK issue, originally April 30; new November 26, **10:32 PST** follow-up: <https://github.com/microsoft/WindowsAppSDK/issues/6439#issuecomment-7200585243>. A contributor reproduces PRI175/PRI252 with a WinForms app and an SDK notifications class library: MakePri expects a RID-suffixed library PRI path. They report clean publishing/startup after setting the library’s `RuntimeIdentifier=win-x64` only for single-file publish; the corresponding <https://github.com/Lake1059/LakeUI/pull/6> remains open. The hardcoded RID needs adapting for ARM64. This library lacks WinUI framework resources, so the result does **not** solve the original multi-MAUI-library PRI277 duplication problem. Reporter-tested, not Microsoft-confirmed.

## microsoft-ui-xaml — past 24 hours

**Exact window:** November 26, **08:31:21 PST** → November 27, **08:31:21 PST**. Issues and Discussions inspected directly through read-only GitHub REST/GraphQL, including older threads’ comments/replies and meaningful linked-source activity; routine labeling excluded.

- **SVG decoding: new benchmark explanation on an old proposal.** Issue originally November 21, 2020; fresh contributor comment November 26 at **23:39 PST**: <https://github.com/microsoft/microsoft-ui-xaml/issues/3666#issuecomment-7212696238>. Decoding gets a separate multithreaded D2D factory: SVG decodes still serialize on their own lock but no longer hold the render lock. With 120 heavy SVGs, the author reports the longest UI stall falling from 12–15 seconds to 0.4–0.6 seconds and peak commit from 363 MB to 247 MB. <https://github.com/microsoft/microsoft-ui-xaml/pull/12810> merged before this window; today’s development is the explanation, not a new merge. Benchmarks were not independently reproduced; shipment unverified.

- **Variable-size ComboBox crash gains a targeted proposal.** Issue originally November 11: <https://github.com/microsoft/microsoft-ui-xaml/issues/12637>. November 26 at **11:24 PST**, it linked newly opened <https://github.com/microsoft/microsoft-ui-xaml/pull/12858>, proposing per-index height caching and a stable fallback to stop popup-height oscillation during virtualized scrolling. The author reports a crashing unchanged-main test and a passing patched test. Both issue and PR remain open. The original reporter’s equal-row-height workaround remains a mitigation, not evidence this candidate has shipped.

- **Ribbon/theme exception reported only with the debugger attached.** New issue November 27 at **00:46 PST**: <https://github.com/microsoft/microsoft-ui-xaml/issues/12866>. A 2.7.0 sample reportedly raises `ArgumentException`/`0x80070057` when returning to a Ribbon tab after changing theme under Visual Studio 2026. The reporter explicitly says it runs normally without the debugger. This is a debugging-workflow report, not a verified framework-wide runtime crash; the sample was not executed.

- **RadioButtons null event entries reportedly persist in 2.7.0.** Issue originally September 9, 2020; fresh November 26 **17:20 PST** comment: <https://github.com/microsoft/microsoft-ui-xaml/issues/3268#issuecomment-7207216426>. A user says the old `SelectionChanged` problem remains in SDK 2.7.0. Handlers assuming every selected/deselected entry is non-null may fail; defensive handling is prudent. This is a one-line retest claim, with no new diagnosis or confirmed fix—not proof of a newly introduced regression.
